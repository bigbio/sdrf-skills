# PXD039066 — annotation report

**Artifact:** `annotations/PXD039066.sdrf.tsv` — 76 rows × 44 columns
**Status:** NOT REVIEWED — produced by the annotator; requires `sdrf-adversarial-review` before contribution
**Validation:** `parse_sdrf validate-sdrf` (sdrf_pipelines 0.1.5) — "Most seems to be fine. There were only warnings." One warning, demonstrated below to be a validator defect.

## Study

Method-optimization study: tuning trapped ion mobility (TIMS) ramp/accumulation time and ion mobility
range on a timsTOF SCP for low-input and single-cell label-free DDA-PASEF, then applying the optimized
settings to cellenONE-sorted human **primary T cells** (1, 5, 10, 40 cells per well).

| | |
|---|---|
| Publication | PMID:37395315 / PMC10370902 / doi:10.1039/d3an00080j — Analyst 2023;148(15):3466-3475 (open access, full Methods read) |
| Instrument | **timsTOF SCP**, DDA-PASEF, label-free (MSFragger 3.4 / FragPipe 17.0) |
| Isolation | cellenONE (Cellenion), 384-well plate, 8–14 µm diameter / max elongation 1.8 |
| Screen row | `include` — label free, carrier=no, n_single_cells=3 |

Primary T cells were negative-selected (RosetteSep) from a healthy-volunteer blood cone under Mayo
Clinic IRB #1039-03.

## Templates

`ms-proteomics v1.1.0`, `human v1.1.0`, `single-cell v1.0.0`.

**No `cell-lines`, and this is forced rather than preferred.** The deposition mixes primary T cells with
a commercial HeLa digest standard in one submission. `cell-lines v1.1.0` declares
`characteristics[cell line]` as `required` with `allow_not_available: false` **and**
`allow_not_applicable: false` — it has no legal value for a primary T cell. Declaring `cell-lines` would
therefore make the 69 primary-cell rows unannotatable. Verified by resolving the template, not assumed:

```
cell-lines 1.1.0  characteristics[cell line]  required  nAv=False nAp=False
```

`single-cell` is safe for the 64 non-single-cell rows because both of its `required` columns
(`single cell isolation protocol`, `cell identifier`) carry `allow_not_applicable: true`.

No `dia-acquisition` (DDA-PASEF). No `clinical-metadata` (no `genotype`/`phenotype` column is used, and
no per-donor clinical data exists).

## Key decisions and evidence

### Every acquisition parameter was read from the raw data, not inferred

The paper gives ramp time only as a range ("varied from 50 to 200 ms") and never says which run is which.
Rather than trusting filename tokens, I extracted `microTOFQImpacTemAcquisition.method` (~220 KB) from
**all 77 run paths** by range-reading the zips — deliberately *not* `analysis.tdf`, which is 143 MB per
run and would have meant ~11 GB of transfer for the same facts.

The method encodes TIMS settings as parallel vectors indexed by `IMS_imeX_Mode`:

```
IMS_imeX_Mode = 3
IMS_imeX_RampStart = [0.78, 0.5, 1.29, 0.70, 0.6]   → 0.70
IMS_imeX_RampEnd   = [1.74, 1.8, 1.45, 1.30, 1.6]   → 1.30
IMS_imeX_RampTime  = [41.4, 248.5, 2484.6, 180, 105.8] → 180
```

**The decode is self-validating:** the extracted ramp time matches the filename token on every run of the
ramp series (50→50, 100→100, 150→150, 180→180, 200→200). Results:

| | runs | ion mobility (Vs cm⁻²) | ramp |
|---|---|---|---|
| OptimizationRamp, non-IMmod | 35 | **0.6 – 1.6** | 50/100/150/180/200 ms |
| everything else (IMmod, HeLa, sorted cells) | 41 | **0.7 – 1.3** | 180 ms |

This confirms the paper's claim and populates `comment[ms min im]` / `[ms max im]` as *measured* values.
It also shows the HeLa dilution series and the sorted cells were run on the optimized settings.
`configuration` in every method file contains `timsTOF_SCP`, independently confirming the instrument,
and `Energy_Ramping_Collision_Energy_StartEnd = [20, 59]` in all 77 matches the paper's stated CE ramp
exactly → `comment[collision energy] = 20 eV;59 eV`.

### Search settings came from deposited `fragger.params`, and they resolve a paper ambiguity

Tolerances are **stated nowhere in the paper**. The deposited FragPipe configs give them:
precursor ±20 ppm, fragment 20 ppm (`units = 1` = ppm) — consistent across all four searches.

> **Caveat recorded, not annotated:** `calibrate_mass = 2` makes MSFragger re-optimize the fragment
> tolerance per run; the pepXML headers accordingly report 10.0–15.0 ppm rather than 20.0. The SDRF
> carries the **configured** 20 ppm, since that is the search setting; the per-run values are an
> internal calibration artifact.

**Modifications differ between the two sample classes, and the deposited params confirm the paper
verbatim** — this is the reason the mod columns are not uniform:

| | fixed | variable |
|---|---|---|
| diluted peptides (T cell + HeLa) | `add_C_cysteine = 57.021460` → Carbamidomethyl C | Ox M; Acetyl protein N-term |
| sorted cells | **absent** | Ox M; Acetyl protein N-term **and K**; Phospho STY |

The absence of carbamidomethyl for sorted cells is not an omission: the cellenONE prep is 2% DDM + TEAB
+ trypsin, with **no reduction or alkylation step at all** — hence `comment[reduction reagent]` and
`comment[alkylation reagent]` are `not applicable` on those 12 rows. The diluted-peptide prep does use
DTT and IAA (PRIDE:0000608 / PRIDE:0000599).

MSFragger's `42.010600 [^K` (sorted) means protein N-terminus **plus** lysine, so it is split across two
SDRF columns: `PP=Protein N-term` and `TA=K`. The positional value is in `PP=`, never `TA=`.
`UNIMOD:1 = Acetyl` and `UNIMOD:21 = Phospho` — verified live, not swapped.

The HeLa search deposited no `fragger.params`; its settings were recovered instead from the
`<search_summary>` header of a HeLa pepXML (streamed, partial inflate), showing `add_C_cysteine =
57.021460`, variable Ox M, variable Acetyl protein N-term — i.e. the diluted-peptide settings, as the
paper implies.

### Enzyme: annotated `Trypsin`, but reprocessors should know the search used Trypsin/P semantics

`comment[cleavage agent details] = NT=Trypsin;AC=MS:1001251`. The paper names Trypsin (Thermo 90057) as
the physical digestion reagent, and this column describes sample preparation.

**Flagged for the reviewer:** the deposited search config says `search_enzyme_name_1 = stricttrypsin`
with `search_enzyme_cut_1 = KR` and `search_enzyme_nocut_1 =` (empty) — cleavage after K/R with **no
proline exception**, which is Trypsin/P (MS:1001313) semantics, not MS:1001251. I annotated the wet-lab
reagent because that is what the column means; anyone reprocessing from this SDRF should set Trypsin/P
to reproduce the deposited results. This is a genuine judgment call and the reviewer should confirm it.

## Two spec defects found (neither worked around silently)

**1. `characteristics[mass]` is unusable, so the dilution load is not encodable.** The obvious column for
the study's central variable (10 ng → 156 pg) is `characteristics[mass]` — TERMS.tsv defines it as
"Injected mass of the sample", pattern `number + unit`, and declares `usage = sample-metadata`. **But it
is declared in no template YAML at all** (`grep` across `sdrf-templates/` finds only `tissue mass`,
`tumor mass`, `body mass index`, `biomass`), and it is absent from resolved `sample-metadata`. Per
CLAUDE.md the resolved YAML is authoritative and TERMS.tsv is a glossary, so **`characteristics[mass]`
is licensed by nothing and I did not use it** — using it is precisely the "column not licensed by any
declared template" failure that PXD023366 hit at review round 2.

Consequence: the peptide load survives only in `source name` (`TCell_peptides_625pg`) and
`comment[data file]`. This is a real information loss and a candidate spec fix (either add `mass` to
`sample-metadata.yaml` or drop it from TERMS.tsv).

**2. Ramp/accumulation time has no column.** The 35 OptimizationRamp runs differ *only* by ramp time,
which no licensed column can express. Those rows are therefore distinguished by `source name` +
`comment[data file]` + `comment[technical replicate]` alone. The IM range half of the optimization *is*
encodable (`ms min/max im`) and is annotated; the ramp half is not.

## Validation output

```
WARNING: Term: NT=T cell;AC=CL:0000084 in column 'characteristics[cell type]',
         is not found in the given ontology list cl;bto;clo
Most seems to be fine. There were only warnings.
```

**This warning is a `sdrf-pipelines` defect, and CL:0000084 is correct.** `validators.py` lowercases the
cell value (`validate_ontology_terms` → `cell_value.lower()`) and then issues an `exact=True` OLS query,
but OLS exact matching is case-sensitive. Reproduced directly against the library's own client:

```python
c.search(term='t cell', ontology='cl', exact=True)  # → no label == 't cell'   (warns)
c.search(term='T cell', ontology='cl', exact=True)  # → [('T cell', 'CL_0000084')]  (correct)
```

`epithelial cell` and `normal` pass only because their labels are already all-lowercase. The accession
was independently verified live via OLS (`searchClasses(query="T cell", ontologyId="cl")` →
`CL:0000084`, exact, `numFound: 1`). Renaming the term to silence the validator would be wrong, so the
warning is accepted.

The `ms min/max mz` columns initially errored: TERMS.tsv documents them as "numeric (m/z)", but the
`mz_value` validator requires the unit suffix (`100m/z`). Fixed to `100m/z` / `1700m/z` — a second, minor
TERMS.tsv-vs-YAML discrepancy.

## Inferred vs stated

- **Stated in paper:** cellenONE isolation, cell counts, m/z range 100–1700, CE 20→59 eV, trypsin, DDA-PASEF, DTT/IAA, mods per class, timsTOF SCP.
- **Read from deposited raw/search files (stronger than the paper):** per-run ramp time and IM range, tolerances (20/20 ppm), fixed carbamidomethyl per class, instrument model, the run-920 duplication.
- **Inferred:** `comment[dissociation method] = beam-type collision-induced dissociation (MS:1000422)`. The paper never names the fragmentation mode. It is inferred from instrument architecture — timsTOF SCP is a QTOF fragmenting in a collision cell downstream of the quadrupole, and the method file's `Energy_Ramping_Collision_Energy_*` confirms a collision-cell CE ramp. Flagged for reviewer scrutiny as the one non-evidenced technical value.
- **Convention, not evidence:** `comment[technical replicate]` is numbered sequentially by acquisition order within each `source name` (1–8 for most dilution sources, 1–9 for `TCell_peptides_2ng`). The 5 ramp runs are not replicates in the usual sense; they are repeat injections of one sample under different settings, and the numbering only enumerates them.
- **PRIDE vs paper conflicts:** none. Unusually, PRIDE's `instruments` field (`timsTOF SCP`) agrees with the paper *and* the raw headers. PRIDE's `modifications` field ("phosphorylated residue", "acetylated residue") is incomplete rather than wrong — it omits oxidation and carbamidomethyl; the deposited search configs were followed.

## Factor

`factor value[cells per well]` — the study's headline biological claim ("365, 804, 1116 and 1651 proteins
from single, five, ten and forty T cells"). It is `not applicable` on the 64 dilution rows, which belong
to the instrument-optimization arm and have no cell-count axis. A single factor cannot span both arms of
this deposition; the alternative axis (peptide load) is unencodable for the reason given above.
