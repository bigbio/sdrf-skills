## Focus questions

**1. Is the channel map's source (the first author's thesis) acceptable?**
Yes. The thesis is Hertel (née Kalb), Goethe University 2021, doi:10.21248/gups.62688, and was re-downloaded. The quotes check out word for word:
- Figure 3-4 legend: "Comparison was done between USP32KO (heavy) and NHT (light)".
- Section 3.4 and Methods 6.2.10.1: "RPE1 NHT and USP32KO cells … light (K0R0) or heavy (K8R10)".

The thesis describes the same experiment as this deposit:
- Its Methods 6.2.10.1 LC-MS and MaxQuant text is identical to the PRIDE protocol (58-min gradient, top10/top15, "MaxQuant 1.5.1 … SILAC quantification (K8)").
- The files are named `AlexK` (Alexandra Kalb).

The map also holds against the deposited data. GlyGly (K)Sites.txt, `Ratio H/L normalized`, log2 for A1/A2/A3:

| site | A1 / A2 / A3 | thesis Fig 3-4C |
|---|---|---|
| Rab7A K191 | 1.57 / 1.66 / 1.42 | 1.50 |
| Rab7A K194 | 1.61 / 1.60 / – | 1.56 |
| Rab11A K179 | 0.79 / 0.66 / 0.86 | 0.77 |
| Rab11B K179 | 0.99 / 0.93 / 0.89 | 0.98 |
| TMEM192 K246 | – / 2.63 / 2.55 | 2.59 |

Positive H/L = KO/NHT, so heavy = USP32KO. This satisfies rule 6: an explicit statement plus a data check.

**2. Is the replicate encoding (1 biological, 3 technical) right?**
Yes. The thesis says "one SILAC sample set with three technical replications". MaxQuant summary.txt puts the AlexK files into experiments A1–A3 (diGly) and a1–a3 (total), each with fractions 1–6, so technical replicates are 1–3. There is one culture per genotype, so biological replicate = 1 in each factor group (rule 3). Fraction mapping matches summary.txt with 0 mismatches. GGIP suffixes _4, _5, _6, _7, _85, _12 give fractions 1–6, matching the SCX pH steps 4.0, 5.0, 6.0, 7.0, 8.5, 11.0. Pairing the total-proteome replicates a*n* with the diGly replicates A*n* by number is an assumption, and it is disclosed.

**3. Are the 36 blocked "Mila" runs (BLOCKED.md) rightly excluded?**
Yes:
- No source describes them: not PRIDE, the thesis or the USP11 paper (PMC8546420). A Europe PMC search for "PXD024211" returns no hits.
- The M1–M3 diGly ratios for the USP32 marker sites are flat (Rab7A K191: 0.02, −0.19, 0.12). So these runs are neither a USP32 replicate nor a label swap; a swap would give negative values.
- USP11 total-protein H/L in m1/m2 is 0.61/0.42 (A series: 0.98, 0.89, 0.90). This matches the BLOCKED.md hint, but no source states it. Blocking the runs follows rule 7.
- BLOCKED.md lists all 36 files. The PRIDE file list confirms that the 36 RAW missing from the SDRF are exactly the Mila files.

**4. Is it right that only Lys8 is listed, although Arg10 was used in culture (rule 5)?**
Yes. summary.txt has `Labels1 = Lys8` (Multiplicity 2) for every file in both searches, and PRIDE says "activated SILAC quantification (K8)". Rule 5 says modification parameters describe the search, so leaving out UNIMOD:267 is correct. The Arg10 culture fact is disclosed in the manifest limitations.

**5. Is the post-build second cleavage column correct, including `not applicable` on the total-proteome rows?**
It is correct:
- Thesis 6.2.10.1: the diGly arm was digested in solution with Lys-C and then trypsin; the total proteome was digested in gel with trypsin only.
- The PRIDE protocol says the same.

The post-build step is deterministic: re-running `postbuild.py` on the two build parts reproduces the artifact byte for byte (same sha256).

`sdrf-tools reconcile` on the full file exits 1 with `cleavage_agent_contradicted 'not applicable'`. I reproduced this and traced it to the tool:
- `check_cleavage_agent` in `tools/record_reconcile.py` passes reserved words to `term_name()`. The `_declared()` filter exists but is not used there.
- The diGly rows alone reconcile with exit 0.

The producer's refutation therefore holds (see minor finding 1). The PRIDE v3 API returned HTTP 500 during the review, so reconcile was run on a v3-shaped record built from the MCP `get_project_details` output.

**6. Is `not available` right for precursor tolerance?**
Yes. parameters.txt (both searches) records only the MS/MS tolerance: FTMS 20 ppm, which is used as the fragment mass tolerance. summary.txt has no peptide tolerance, and no mqpar.xml was deposited. Filling in the MaxQuant default (4.5 ppm) would be inference. The runs were searched, so the value is `not available`, not `not applicable` (rule 5). The consequence is that convert-openms fails, which is expected and was noted in validation.txt.
