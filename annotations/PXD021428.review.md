## Findings

### IMPORTANT-1: recommended `characteristics[sample storage temperature]` omitted although evidence exists, and the manifest says it is "not reported"
- Location: file level (column absent); manifest `limitations[8]` ("Passage number, cell type, storage temperature not reported").
- Evidence: the cell-lines v1.1.0 template marks `characteristics[sample storage temperature]` as **recommended** (pattern number + °C). iScience STAR Methods (PMC8957019): "Mixed super SILAC standard was then aliquoted and stored at -80°C." Campaign rule 9 (binding) requires recommended columns the templates license to be added when evidence exists. The limitation statement is therefore factually wrong for the heavy channel.
- Fix: add `characteristics[sample storage temperature]` (after `characteristics[culture medium]`, template order) with `-80 °C` on the 378 SILAC-heavy rows. Use `not available` on the 378 light rows: the tumours were "snap-frozen in liquid nitrogen", but no storage temperature is stated for them. Rebuild with `sdrf-tools build` so the column comes from the build, not a post-build edit. Add a manifest claim citing iScience and correct the limitation.

### Minor
1. **`characteristics[organism part]` = `prostate`** (378 light rows) is an exact synonym. The UBERON:0002367 label is `prostate gland` (BTO:0001129 too), and the validator warns on `prostate`. Prefer the canonical label; this is not blocking, because the synonym resolves and the curated corpus uses it.
2. **Optional cell-line columns with evidence**: `characteristics[cell line authentication]` can be "STR profiling (Promega GenePrint 10 System)" (iScience). `characteristics[biorepository]` can be ATCC for LNCaP clone FGC / 22Rv1 / VCaP, Case Western Reserve University for CWR22Res and Newcastle University for LNCaP-AI (preprint). Both columns are optional.
3. **Super-SILAC naming consistency**: `characteristics[pooled sample]` `SN=…;SN=LNCaP;…` and the heavy `characteristics[cell line]` text say "LNCaP", while the light rows use `LNCaP clone FGC` for the same line. Consider `SN=LNCaP clone FGC` (or note that the SN= tokens name cell-line lysates, not source names in this SDRF; this follows the PXD017530 precedent).
4. **`characteristics[individual]`** values `CWR22_donor` / `LNCaP_donor` / `VCaP_donor` are curator-made labels, not study IDs. The grouping is supported (Cellosaurus HI; preprint "variant of CWR22"), but the manifest should say these are synthetic donor keys.
5. **Mixed-species tissue**: in my proteinGroups pass, mouse-only protein groups account for about 31 % of the light-channel intensity, and PRIDE lists both Homo sapiens and Mus musculus. Annotating `Homo sapiens` plus `characteristics[xenograft]` follows the TERMS.tsv xenograft rule and is disclosed in the limitations. Consider adding the mouse share to the limitations, so downstream users know the light channel is not purely human.
6. **`comment[data file]` uses the inner `.raw` name, while the repository serves `<stem>.zip`.** Spec README.adoc:444 allows recording the archive. The `.raw` choice is consistent with mqpar and summary, and I verified the zip members. Note that a consumer downloading by `comment[data file]` will not find `.raw` on the FTP (no `comment[file uri]`).
7. **iScience RRID conflict** (CVCL_4783 LNCaP C4, CVCL_LI38 CWR22Pc vs the preprint's ATCC CRL-1740 / CWR22Res) is recorded only in the manifest limitations. Keep it in the report too; no change to the values is needed.
