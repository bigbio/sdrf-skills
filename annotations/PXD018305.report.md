## Key decisions with evidence
1. **The SILAC IP arm is excluded (rules 6/7).** The sources disagree:
   - The paper and the PRIDE protocol list wt, S276L and empty, then ("light":"medium":"heavy").
   - Table S3.1 states: empty = Light in BR1-3; S276L = Medium/Heavy/Medium; wt = Heavy/Medium/Heavy.
   - The deposited data support empty = light, because RUNX1 is lowest in L in IP_01 and IP_02. That refutes the prose.
   - The data lean against the table's medium/heavy assignment. The only S276L-specific peptide (`QIQPSPPWSYDQSYQYLGSIASPSVHPATPILPGR`) is in **Medium** of IP_RUNX1_02, which is Table BR2 (verified: Table S3.2 IP_Runx1_01/02 vs the deposited IP_RUNX1_01/02 give log2 r 0.97/0.94, and S3.1 BR*n* sums onto S3.2 exp0*n*). The table says Heavy there. HDAC1 in BR1 and the authors' own averaged wt_emp column also fit the inverse assignment.
   - The third deposited run, `20190514_MaS_RUNX1_IP_02` (5% MS/MS identified), shares only 232 of Table BR3's 1848 peptides. It is probably not the published replicate.

   No source survives the data check, so the 3 runs are left out rather than given a wt/S276L identity that may be wrong.
2. **Phospho rounds are fractions of a phospho source.** The Methods describe "ten rounds of phosphopeptide enrichment" per replicate. Files `_phospho_R<n>_F1-10` become fraction identifiers 1-10 of `A375<S|R>_BR<n>_phospho`, with `characteristics[enrichment process]` = enrichment of phosphorylated protein. The proteome of the same replicate is a separate source with the same biological replicate number. This follows the PXD010683 precedent.
3. **Modifications per arm (rule 5).** These come from summary.txt per file and the mqpar parameter groups.
   - All runs: Carbamidomethyl C fixed; Oxidation M and Acetyl Protein N-term variable.
   - The 60 phospho runs and the 12 pulldown runs also have Phospho STY variable.
   - The 54 proteome runs were searched without Phospho, so that column is `not applicable` on those rows.
   - The paper says only "phosphorylation" globally; the deposited searches are what is annotated.
4. **Cleavage (rule 2).** Both protocols use Lys-C (3 h), then trypsin overnight. Trypsin and Lys-C each get a `comment[cleavage agent details]` column. MaxQuant searched Trypsin/P.
5. **Instruments and NCE.** HTTP range reads of all 129 raw headers give Exploris 480 = 114 screen-1 files, Q Exactive HF = 12 pulldown files, and HF-X = only the 3 excluded IP files. NCE is 28 (paper; Exploris method header) and 27 (QE HF method header of 4 pulldown/input files).
6. **Phenotype wording.** The resistant line was generated against PLX4720, the vemurafenib analogue; the paper says it calls this "vemurafenib" only for simplicity. The values are therefore `PLX4720 sensitive` / `PLX4720 resistant`. The precedent PXD010683 wrote "vemurafenib …".
7. **Cell-line identity.** A375 is ATCC CRL-1619, so CVCL_0132 / A-375. The resistant derivative (Sinnberg et al. 2016) has no Cellosaurus entry. I checked the CVCL_0132 children: A375-R CVCL_6234 and A375/R CVCL_IW10 are different lines. The parental accession is used for both, as in the precedent. The following come from Cellosaurus: skin of leg (UBERON:0001511), amelanotic melanoma, 54Y, female, adult, and European ancestry (from "Caucasian").
8. **Pulldown input runs.** Their bait is "pull-down input lysate (no bait)", not `not applicable`. That keeps them from pooling with the main-screen A375 S proteome condition in convert-openms. Table S3.3 compares only S276 / L276 / beads.

## Judgement calls a reviewer should attack hardest
1. **Excluding the SILAC IP arm** even though Table S3.1 gives an explicit per-replicate label table. The counter-evidence is individually weak: one low-scoring peptide (PEP 0.043, H/M 0.62), one HDAC1 ratio set, and the authors' internally inconsistent averages. It does all point the same way, and replicate 3 is not tied to the deposited run. An alternative would be annotating `_R1`/`_R2` per Table S3.1 as a separate `-silac` file and recording the conflict.
2. **Phospho F1-F10 as enrichment-round fractions** with fractionation method `not applicable`, instead of hpH fractions.
3. **Factor design in one file.** I used `phenotype` + `bait`, with an explicit input-lysate bait value and `not applicable` bait on the main screen. The alternatives are splitting the main screen and the pulldown into separate SDRFs, or using parental CVCL_0132 for A375 R.
