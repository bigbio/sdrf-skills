## The key finding: the file→sex map is in the deposited data

This dataset's entire scientific content is a male-vs-female contrast, so an SDRF without a
per-file sex assignment would be worthless. Neither the manuscript, the figures, nor PRIDE names a
single raw file. The map came from the **deposited Proteome Discoverer `.msf` result files**, which
are SQLite databases carrying a `StudyInformation` table with PD's study-factor columns:

```
StudyFileID | SampleIdentifier          | SampleGroup | ReplicateGroup   | BFGender
F1          | 20230901_PatchClamp_094   | Control     | Control,Male     | Male
F6/F7/F8    | ..._101 / ..._102 / ..._103 | Control   | Control,Male     | Male
F2..F5      | ..._097 / _098 / _099 / _100 | Sample   | Sample,Female    | Female
```

The `.msf` files are 500–700 MB each; I did not download them. The tables were read by parsing the
SQLite header, resolving each table's root page from `sqlite_master`, and HTTP range-fetching only
those pages from the PRIDE FTP mirror — a few KB per file.

**This map is independently corroborated**, which is why I trust it:

1. **Autosampler vial positions** (Thermo raw headers, first 256 KB, utf-16-le): males occupy
   `G:C1–C4` (sequence rows 19–22), females `G:C9, D1, D2, D3` (rows 27–30). The two clusters fall
   out of the raw files *without reference to the .msf* and partition the runs identically.
2. **Acquisition timestamps** (`WorkflowInputFiles.CreationDate`): all four males 2023-09-01
   16:10 → 22:38, all four females 2023-09-02 00:47 → 07:15, uniformly ~2 h 09 min apart
   (90-min gradient + wash). The chronological order is 094, 101, 102, 103, 097, 098, 099, 100 —
   again the same 4+4 split.
3. **Counts**: 4 male + 4 female matches Table 1 exactly.

**`SampleGroup` = "Control" (male) / "Sample" (female) is a Proteome Discoverer study-design
artifact and was deliberately NOT annotated.** The paper treats the sexes symmetrically; neither
sex is a control. Transcribing PD's label into `characteristics[disease]` or `[treatment]` would
have invented an experimental condition that does not exist.

## Key decisions and evidence

**Instrument — PRIDE, paper, and raw headers all agree** (unusually). `Orbitrap Eclipse`
(`MS:1003029`), confirmed three ways: PRIDE's `instruments` field, the Methods, and the Thermo raw
file headers (`Orbitrap Eclipse`, `Jin_SC_90min_HCD_OTIT_Turbo_FAIMS_2CVs_500mm_B2-40_DI.meth`,
software 4.0.4091) plus `WorkflowInputFiles.InstrumentDescription` in every `.msf`. No conflict to
resolve.

**Cell type — verified against the CL definition, not the label.** The screen row proposed "locus
coeruleus noradrenergic neuron"; **no such CL term exists.** OLS returns only GO process terms and
UBERON:0002148 for that phrase. The correct term is `noradrenergic neuron` **CL:0008025**, defined
as *"A neuron that release noradrenaline (noriphinephrine) as a neurotransmitter"* — which is what
the Dbh-Cre/tdTomato reporter actually establishes (Cre driven from the endogenous *Dbh* locus).
Its only child is `sympathetic noradrenergic neuron` (CL:3000002), which LC neurons are **not** —
the LC is a brainstem CNS nucleus, not a sympathetic ganglion. So CL:0008025 is the most specific
defensible term; the anatomical restriction is carried by `characteristics[organism part]` =
`locus ceruleus` UBERON:0002148 (OLS's label spelling; the paper uses "coeruleus").

**`characteristics[single cell isolation protocol]` = `manual picking` (an inference).** The
resolved template makes this column `required` with `allow_not_available: false`, so an enum member
was mandatory; the enum is `FACS, cellenONE, microfluidics, laser capture microdissection, manual
picking, nanoPOTS, droplet microfluidics, acoustic droplet ejection` and **patch-clamp aspiration is
none of them verbatim.**

- `not applicable` *is* permitted by the resolved template (`allow_not_applicable: true`) — note this
  contradicts `TERMS.tsv`, which claims `allow_not_available: true` for this column; per the brief I
  trusted the **resolved template**. I rejected `not applicable` anyway: an isolation protocol
  plainly *does* apply here, it is simply outside the enum, and `not applicable` would assert
  something false.
- `manual picking` is the closest defensible member: a human operator visually identifies one
  tdTomato-positive neuron under IR-DIC + fluorescence and collects it with a hand-guided glass
  micropipette. It is manual, one-cell-at-a-time selection — the enum's other members are all
  automated or instrument-mediated and are each positively contradicted by the Methods (no cell
  sorter, no chip, no laser, no dispenser).
- The enum validator's `error_level` is `warning`, and the value passes cleanly regardless.
- Same call, same reasoning as `PXD023366`.

**`characteristics[cells per well]` = `1`, and the caveat is real.** Each aspirate derives from
exactly one neuron, so `1` is correct as "number of cells contributing to this reaction" (the
column's pattern is `^\d+$`; there is no fractional option). But the Methods support **soma
contents, not a whole cell**: the pipette aspirates the cytoplasm of the patched soma, and the
authors themselves report the profile "predominantly reflects a substantial pool of neuronal soma"
with only ~5% membrane proteins and **0.8% plasma-membrane-spanning** proteins — a composition
consistent with cytoplasmic aspiration rather than whole-cell lysis. `characteristics[material
type]` = `cell` is the closest enum member (the fixed enum is `tissue, cell, cell line, organism
part, whole organism, synthetic`); there is no "subcellular fraction" member.

**No fixed modification — and that is not an omission.** The protocol goes straight from aspirated
cell contents to trypsin/Lys-C in the same PCR tube: **there is no reduction and no alkylation
step.** Accordingly the only modification is `NT=Oxidation;AC=UNIMOD:35;TA=M;MT=Variable` — the sole
variable mod in the deposited search ("variable modifications, +15.995 Da (oxidation) on
methionine"). No `Carbamidomethyl`: adding it would be a fabrication, and the contrast with
`PXD023366` (which *does* have an IAA step) is deliberate.

PRIDE's `modifications` field says `monohydroxylated residue`, which is the PSI-MOD framing of the
same oxidation — consistent, not a conflict.

**`comment[cleavage agent details]` = `NT=Trypsin;AC=MS:1001251` (a deliberate simplification).**
The reagent was a **trypsin/Lys-C mix** (Thermo A40009), but the deposited search declared
`enzyme, trypsin (full)`, 2 missed cleavages. **No `Trypsin/Lys-C` term exists in PSI-MS** (OLS
returns `Lys-C` MS:1001309, `Lys-C/P` MS:1001310, `Trypsin` MS:1001251 — no mix). Annotating
Trypsin matches both the search that produced the deposited results and the effective specificity
(trypsin cleaves after K and R; Lys-C's K-specificity is a subset), so a reprocessing pipeline
reading this SDRF reproduces the deposition. Splitting it into two cleavage-agent columns would
describe the reagent while misdescribing the search. Recorded here so the choice is auditable.

**Search settings** (all from Methods, consistent with PRIDE's `data_processing_protocol`):
precursor 10 ppm, fragment **0.6 Da** (ion-trap MS2 — note this is Da, not ppm), Sequest HT,
Percolator FDR 0.01 strict, UniProt mouse (17,082 entries, Oct 2021).

**Strain** is annotated in full (`characteristics[strain or breed]`, free text): Dbh-tdTomato =
B6.Cg-Dbh<tm3.2(cre)Pjen>/J (JAX #033951) × B6.Cg-Gt(ROSA)26Sor<tm14(CAG-tdTomato)Hze>/J (Ai14, JAX
#007914), both congenic on C57BL/6J. This is load-bearing: the tdTomato reporter is *how* the
noradrenergic identity in `characteristics[cell type]` is established.

**`characteristics[developmental stage]` = `adult` (EFO:0001272)** — cohort-level evidence, which is
exactly what the brief permits for this column: the PC/SCP mice are 54 ± 0.8 (F) and 55 ± 3.5 (M)
days old, unambiguously adult, and the title says "adult mouse".

**`characteristics[disease]` = `normal` (PATO:0000461)** — healthy wild-type-background reporter
mice; no disease model anywhere in the study.

## Ages, and what is NOT annotated

Table 1 reports ages as group means ± SD (females 54 ± 0.8, males 55 ± 3.5 days). Per the brief's
demographic rule these are **cohort summaries, not per-sample values** — even had an `age` column
been licensed, they could not be assigned to individual neurons. Not annotated.

Mouse identity is likewise not annotated: each neuron came from a different mouse (4 mice, 4 neurons
per sex), which `characteristics[biological replicate]` 1–4 within each sex faithfully encodes, but
no source names the individual animals.

## Design note (recorded, not a defect)

**Sex is perfectly confounded with acquisition batch.** All four males were acquired on 2023-09-01
(16:10–22:38) and all four females on 2023-09-02 (00:47–07:15) — a clean temporal split with zero
interleaving. Any instrument drift across that boundary is indistinguishable from the sex effect the
study reports. This is a property of the deposition, and the artifact records it faithfully via
`comment[acquisition date]`; annotating that column is what makes the confound visible to downstream
reuse. Flagging it for the reviewer as a design observation, not an annotation error.

The FAIMS dual-CV acquisition (−55/−70 eV within one run) is **not** fractionation:
`comment[fraction identifier]` = 1 for every row.
