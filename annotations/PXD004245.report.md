## Technical values (HeLa SILAC)
- Instrument: **raw headers** — 8 runs Q Exactive Plus (MS:1002634), occupancy run Q Exactive HF
  (MS:1002523). PRIDE says "Q Exactive" → overridden (paper Methods also says Q Exactive Plus; the
  paper intro's "Q Exactive HF" applies only to the 2015 runs).
- Modifications from the deposited MaxQuant output (no mqpar.xml): fixed Carbamidomethyl C
  (parameters.txt); variable Oxidation M, Acetyl Protein N-term, ADP-Ribosyl (UNIMOD:213) on K,R,D,E
  (modificationSpecificPeptides.txt); SILAC Label:13C(6)15N(2) K (UNIMOD:259) and
  Label:13C(6)15N(4) R (UNIMOD:267) as Variable (corpus convention).
- Tolerances: fragment 20 ppm (parameters.txt), precursor 7 ppm (paper). DDA, HCD.
- Cleavage agent: `NT=Trypsin;AC=MS:1001251`. Per the coordinator's correction, this column is the
  **digestion enzyme**, not the search rule.
  - **Search-rule note** (recorded in the manifests): MaxQuant 1.3 `parameters.txt` has no enzyme
    row, and no `mqpar.xml` was deposited. In a 60 MB sample of `msms.txt`, all 2789 PSMs with an
    internal K-P/R-P bond have `Missed cleavages` values that leave that bond out. So the search used
    MaxQuant **Trypsin**, not Trypsin/P.
  - **Lys-C is not in a column.** The Methods say the digest used Lys-C as well as trypsin, and the
    coordinator approved a second column. But `comment[cleavage agent details]` is single-cardinality
    in ms-proteomics v1.2.0, so `sdrf-tools build` writes only one column, and I did not hand-edit the
    SDRF. Lys-C is a recorded limitation. Adding it needs a build/contract change or an explicit
    override (1715 files in the community corpus do repeat this column).
- `comment[sdrf version]` = `v1.1.0`, the spec version in README.adoc line 27 (coordinator decision).
  `comment[sdrf template]` keeps `NT=ms-proteomics;VV=v1.2.0` (bigbio/sdrf-templates HEAD 7da1747
  templates.yaml line 150 `latest: 1.2.0`).
