### Findings

1. **important** (file_mapping) — file: ALI1442-S18-A-KCA-R.raw (missing from comment[data file]); BLOCKED.md PXD016512 section; manifest limitations: The run was excluded as "presumed not searched", but the deposited search output shows it was searched. In proteinGroups_PRKCA_KCE_KCG.txt the summed intensity of experiment KCAREV1 is 4.68e11, the Q Exactive Plus scale. Every arm of this file that contains exactly one QE run has one experiment at that scale: KCAFOR1 4.65e11 (ALI1442-S02-A-KCA-F, annotated), KCEFOR1 3.73e11, KCEREV1 4.27e11, KCGFOR1 3.39e11 and KCGREV1 3.75e11. All Velos experiments are at or below 4.5e10. KCAREV therefore holds 1 QE and 7 Velos experiments. The 1.5 GB QE run is searched and in scope, and is wrongly omitted. One of the 8 annotated Velos PRKCA REV runs (LDY1208 / LDY1261 / LDY1357 R-1..R-4) is the unaccounted one, or two of them were merged into one experiment. Those rows currently carry search tolerances that may not apply.  
   Evidence: Reviewer download of proteinGroups_PRKCA_KCE_KCG.txt (14 MB); sums of the "Intensity <exp>" columns. Raw header of ALI1442-S18-A-KCA-R.raw: Q Exactive Plus, PC HKC6ZZ1, vial GB6. FTP Content-Length is 1537820789.
   Fix: Add ALI1442-S18-A-KCA-R.raw (3 rows; sources PRKCA_ALI1442_REV_pool1_{HKE3_FLAG-PRKCA,HCT116_EV,HCT116_FLAG-PRKCA}; next biological replicate numbers; the QE technical values of the other ALI1442 rows). Replace the inference in the manifest and BLOCKED.md with the intensity evidence, and record that one Velos PRKCA REV run (or a merged pair) is unaccounted.

2. **minor** (file_mapping) — file: LDY1357-S24-A-PRKCA-R-4_010.raw: The exclusion is defensible, but the stated reason is not the decisive fact. The file is a 39,754-byte stub: header only, no scans to search. Say that in BLOCKED.md and the manifest. Following the request's unsearched-runs rule, it could also be listed with tolerances `not applicable`.  
   Evidence: FTP Content-Length is 39754. Its header gives original name LDY1357-S24-A-PRKCA-R-4.raw and vial BE8.

3. **minor** (provenance) — annotations/PXD016512.validation.txt: The note under validate-sdrf talks about an OLS 500 for 'orbitrap', but the logged error was for 'q exactive plus'. The note was copied from PXD016505.  
   Evidence: validation.txt lines 5-9.

4. **minor** (technical) — comment[fragment mass tolerance] (and comment[collision energy]), all Q Exactive Plus rows: 'not available' on the QE rows makes parse_sdrf convert-openms exit 1. Supp. Methods 12 states one search-wide 'fragment ion mass tolerance set to 0.5 Da' with no instrument restriction; restricting it to the ion-trap rows is an interpretation (MaxQuant 1.3 keeps separate ITMS/FTMS settings, but none is deposited). The HCD NCE was not looked for in the instrument-method stream of the raw files: the first 16 KB hold only the Dionex LC method.  
   Evidence: supp1.txt section 12; convert-openms rerun by reviewer: "Cannot read fragment mass tolerance: not available".

5. **minor** (design) — characteristics[biological replicate], SILAC medium rows of the 17 shared RAC1 raws: The same EV source names get different biological replicate numbers in the two SDRFs: 79-84 in PXD016505 and 40-45 in PXD016512. Each file is consistent on its own, because EV numbering runs over all baits in that file. Every other column of the 51 shared rows is identical. Either note this in both manifests or number the EV pools identically in both files.  
   Evidence: Reviewer diff of the 51 rows (17 files x 3 labels): 17 differing cells, all in characteristics[biological replicate] of the medium channel.
