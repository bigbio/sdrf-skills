### `dia-acquisition` is deliberately NOT declared — the central decision in this file

This is a known, already-documented spec limitation, and PXD044986 is its **second independent
instance** (see `annotations/BLOCKED.md`, section added for PXD024043).

`dia-acquisition/1.1.0` **overrides** `comment[proteomics data acquisition method]` with a `values`
validator admitting the single literal `Data-independent acquisition` at `error_level: error`, plus
`allow_not_applicable: false` / `allow_not_available: false`. **No legal value exists for a DDA row.**

| option | cost |
|---|---|
| declare `dia-acquisition` | the 25 pooled DDA runs become inexpressible and must be dropped |
| omit it (**chosen**) | the 290 DIA runs lose 4 columns — all `recommended`, none `required` |

The 25 DDA runs are **real samples** (20/50 pooled cells, 200 pooled nuclei), not sample-less blanks,
so the brief's scope rule forbids excluding them: exclusion is reserved for runs with *no sample*.
Dropping 25 sample-bearing runs to preserve four recommended columns inverts that rule.

Here the argument is stronger than in PXD024043: the DDA runs build the very spectral libraries the
DIA half is searched against (`Spectral_library_CCA.tsv`, `Spectral_library_Jurkat.tsv`,
`Spectral_library_PEO1_Nuclei.tsv`, all deposited, and the DIA-NN log confirms `--lib`). Declaring
`dia-acquisition` would drop exactly the runs that make the DIA analysis reproducible.

**What is lost, precisely:** `comment[dia method]` = `diaPASEF` (PRIDE:0000650 exists),
`comment[isolation window width]` = `25`, `comment[scan window lower/upper limit]` = `400`/`1000` —
all stated in the paper, all fitting their columns' patterns, all with nowhere to go. Per-row
acquisition truth survives in `comment[proteomics data acquisition method]`, so the file is
**under-described, never wrong**.

**NHC's Cellosaurus accession is left `not available` on purpose — this is the most contestable call
in the file, and it is contestable in the *conservative* direction.** The evidence for
NHC = `H-69` / `CVCL_8121` is strong but circumstantial:

- CVCL_8121 is an SV40-transformed **human cholangiocyte** line (`Cell type: Cholangiocyte;
  CL=CL_1000488`), which matches "normal human cholangiocyte" exactly.
- Its Cellosaurus reference list includes **PubMed=10094943, authored by Gores, Gregory James** — the
  very person who gifted this paper's NHC line.
- "normal human cholangiocyte (H69)" is common usage in the field (Europe PMC, 39 co-mentions).

But **this paper never writes "H69"**, Cellosaurus does not list `NHC` as a synonym of CVCL_8121, and
the Mayo/Gores-LaRusso "NHC" is not provably that line rather than an in-house isolate. Asserting
`CVCL_8121` would validate cleanly and could be wrong; `not available` (legal — `allow_not_available:
true`) cannot be. The brief's rule is "never guess an accession", and the near-miss trap is real:
`NCI-H69` is a **small-cell lung cancer** line, unrelated. Identity is preserved in
`characteristics[cell line]` = `NHC` and `characteristics[cell type]` = `cholangiocyte` (CL:1000488),
both paper-sourced.

`RBE` and `NHC` have **no CLO/BTO/EFO term** (searched all three, exact and fuzzy, 0 hits), so
`characteristics[cell line]` carries the bare name for those two. CVCL_4896 carries RBE's identity.

**The OLS cell-line trap was hit and avoided.** Cellosaurus `idsy:"Jurkat"` returns `LINTERNA
Jurkat`, `Jurkat-TAg`, `Jurkat 1G4`, `Jurkat/A4`, `PPIA-/- Jurkat` in the top 5 — **the parental line
is not among them**. `CVCL_0065` was pinned by direct accession lookup, not by search ranking. Same
for `RBE`, whose fuzzy hits include a *tick* cell line (`RBE/LULS58`, CVCL_C1GX, *Rhipicephalus
bursa*) and several human derivatives.

### The 4 validation warnings are all justified

1. **`NT=T cell;AC=CL:0000084` "not found in cl;bto;clo"** — a **`parse_sdrf` bug**, root-caused, not
   an error in this file. `OntologyValidator.ontology_term_parser` lowercases the `NT` value, then
   passes the lowercased string to OLS as a **case-sensitive `exact` query**. Instrumented:
   `search(term='t cell', ontology='cl', exact=True)` → 100 hits, **none** labelled `t cell`, because
   the real label is `T cell`. Any term whose label contains an uppercase letter warns spuriously;
   all-lowercase labels (`cholangiocyte`, `epithelial cell`) pass. CL:0000084 was verified live in
   both OLS and the validator's own client (with correct case → exact hit). Correctness was kept over
   validator appeasement.
2–4. **`untreated` / `calyculin A` / `DMSO` in `characteristics[treatment]`** — the column's ontology
   validator (ncit/efo, warning level) **contradicts its own specification**: its `description` says
   "Use 'untreated' for controls" and its `examples` are `untreated`, `LPS stimulation`,
   `doxorubicin treatment`, `drought stress` — and `untreated` is not an ncit/efo term (verified, 0
   exact hits). The column is documented as free-text-ish; ontology-grade identity is carried in
   `characteristics[compound]` (`CHEBI:41791` calyculin A, `NCIT:C107506` tazemetostat, `NCIT:C437`
   DMSO), which validates cleanly.

## Open items for the reviewer

1. **`dia-acquisition` dropped** — 4 recommended DIA columns lost to keep 25 sample-bearing runs.
   Matches the PXD024043 precedent and the brief's scope rule, but it is the file's biggest tradeoff.
2. **NHC = CVCL_8121?** I declined to assert it (evidence above). A reviewer with access to a
   Gores-lab methods paper that writes "NHC (H69)" for *this* line could justify filling it.
3. **`cell type` = `epithelial cell` (CL:0000066) for HuCCT-1/RBE/EGI-1/PEO1** — Cellosaurus asserts
   no cell type for these four. Calling malignant lines `cholangiocyte`/`epithelial cell of bile
   duct` would over-claim differentiation state; `epithelial cell` follows PXD052416's HeLa
   precedent. Jurkat's `T cell` is Cellosaurus-asserted; NHC's `cholangiocyte` is paper-asserted.
4. **Two factor columns across three unrelated arms.** `factor value[cell line]` is meaningful only
   within the CCA arm and `factor value[treatment]` only within the Jurkat/PEO1 arms; no experiment
   compares Jurkat to EGI-1. Internally coherent, but a consumer could read the file as one 6-level
   cell-line design. Arguably this deposition is three studies in one accession.
5. **Single nuclei annotated under `single-cell`** with `cells per well = 1` and `sample type = not
   applicable`. The template has no organelle concept at all (`characteristics[organelle]` does not
   exist; `material type` and PRIDE `sample type` both lack the value). The paper's "single organelle"
   claim — half its title — is therefore **not machine-readable in any SDRF column**. Worth raising as
   a spec gap in its own right.
6. **`beam-type collision-induced dissociation`** is inferred from the collision-energy ramp +
   instrument geometry, not stated.
