# PXD035841: SDRF annotation report

**Status: BLOCKED. No SDRF was built.** The deposited SILAC search is not multiplexed, and no source gives the SILAC channel→condition map. The other 48 runs are label-free mouse retina proteomics and phosphoproteomics, which is out of scope for the SILAC campaign. The details are in `annotations/BLOCKED.md`, section "PXD035841".

## Evidence examined
- **PRIDE project record** (title, sample and data protocols). The PRIDE v3 `files` endpoint returned HTTP 500, so the file list came from the MCP `get_project_files` tool and the FTP directory listing: 50 RAW, 4 mqpar XMLs and `checksum.txt`.
- **Paper:** Luu et al., PNAS 2023, PMC10175720. I read the JATS full text and the SI Appendix PDF from the PMC OA S3 bucket.
- **`SILAC-proteomics.xml`**, the mqpar for `SILAC_PROTEOMICS_A.raw` and `SILAC_PROTEOMICS_H2O2.raw`. Its sha1 matches `checksum.txt`. It has multiplicity 1, labelMods `Arg10;Lys8`, and the human UniProt fasta. The PRIDE data protocol and the SI both say "multiplicity was set to two", which contradicts it.
- **`proteomics.xml`**, the mqpar for the mouse label-free runs: mouse fasta, multiplicity 1, no labels.

## Why blocked
1. Campaign rule 14 says multiplicity must be > 1 in the deposited search parameters. It is 1 here.
2. Neither the paper, the SI nor PRIDE says which condition (atRAL, H2O2 or vehicle) is heavy or light. No deposited table carries H/L ratios.
3. The paper describes five comparisons against vehicle, but only two SILAC runs are deposited. The PDE-inhibitor SILAC runs are missing.

## What would unblock it
- The channel map for each of the two SILAC files and the true search multiplicity, from the authors or from deposited multiplicity-2 MaxQuant output.
- The mouse arms could be annotated as label-free outside this campaign, but only once the file codes (`1d`, `NB`, `BC`, `BAY`, `Roli`, `Vard`) are defined.
