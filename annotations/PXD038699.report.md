### Dimethyl channels — verified by MASS via OLS (the known trap)
The channel→UNIMOD mapping was derived from the stated chemistry and mass spacings (Δ0=28.0313; Δ4 spaced +4.0251; Δ8 spaced +8.0444, DIA-NN `--channels`) and each accession confirmed live:
- **Δ0 light** (CH₂O + NaBH₃CN, +28.0313) → `Dimethyl` **UNIMOD:36** — reference pool
- **Δ4 intermediate** (CD₂O + NaBH₃CN, +32.0564) → `Dimethyl:2H(4)` **UNIMOD:199**
- **Δ8 heavy** (¹³CD₂O + NaBD₃CN, +36.0757) → `Dimethyl:2H(6)13C(2)` **UNIMOD:330** (the +8 form; not the +6 UNIMOD:510 that "Dimethyl" smart-lookups return)

Each is written as a **fixed** modification on both peptide N-term (`PP=Any N-term`) and lysine (`TA=K`), in `comment[modification parameters]`. `comment[label]` carries the tooling-canonical PRIDE channel term (`DIMETHYL0`/`DIMETHYL4`/`DIMETHYL8` = PRIDE:0000848/0000850/0000852), which matches the sdrf-pipelines plexDIA converter's dimethyl channel names.

### Modifications — NO Carbamidomethyl (deliberate)
`comment[reduction reagent]` / `comment[alkylation reagent]` = `not applicable`, and **no Carbamidomethyl** anywhere. Directly stated: *"Carbamidomethylation was unselected as samples were not reduced and alkylated."* Only variable **Oxidation (M)** UNIMOD:35 is searched (all rows). Adding Carbamidomethyl would be the classic false-positive that passes validation but is wrong on every row.

## Values deliberately left missing, and why
- `characteristics[sex]` = **`not available`** (all rows). The cohort is explicitly *"male and female"* but the deposited data provide **no per-mouse / per-run sex mapping**. (The 5-shape zip token "…visuallib**males**…" hints these frames are male, but I did not promote a filename token to a per-row assertion for a mixed-sex study — flagged for the reviewer.)
- `characteristics[spatial coordinates]` = **`not available`**, and `factor value[spatial coordinates]` = **`not available`**. Porto-central **zonation is the study's biological factor**, but it is a **computed continuous variable** (PC1 bins / distance-to-central-vein) not deposited in any run-mappable per-cell key; `meta_scDVP.tsv` carries only an `Image_index`, no coordinate or zonation class. Left unmapped rather than fabricated — exactly as the approved sibling PXD062231 did.
- `characteristics[cell identifier]` for the **45 unmapped m1A runs** = the **positional plate-well/channel id** (e.g. `m1A_33_S2-C11_D4`), because the template forbids `not available` in this column; the deposited image-based `cell_ID` does not exist for these wells. Mapped cells use the deposited `cell_ID` (e.g. `m1A_01_target4`).
- **Reference (Δ0) rows:** `cell type`, `cells per well`, `cell identifier`, `single cell isolation protocol`, `lcm microscope model` all = `not applicable` (a bulk-tissue peptide pool, not a microdissected cell); `sample type = pooled`, `biological replicate = 1` (one shared pool).
- Precursor/fragment tolerance for the **five-shape arm** = `not available` (the DIA-NN settings the paper states — 15 ppm — are given only for the 263-file scDVP search; the separate five-shape search settings are not stated).
