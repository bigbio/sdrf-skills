## 5. Key technical decisions (evidence: PRIDE sample/data-processing protocols + paper Methods)

- **Instrument = Orbitrap Astral, DDA, label-free** — stated identically in the PRIDE description, the
  paper, and every raw filename (`…Astral…`). No raw-header re-read performed (all three sources agree).
- **Carbamidomethyl is asserted for BULK rows only.** The PRIDE sample-processing protocol documents an
  explicit alkylation step for bulk: *"Bulk samples were lysed, reduced with DTT, alkylated with IAA,
  and digested with trypsin."* IAA → carbamidomethyl (C) Fixed is therefore evidence-based, not reflex.
- **NO Carbamidomethyl for the SINGLE-CELL rows.** The same protocol states the single-cell samples were
  *"processed without cysteine carbamidomethylation."* Per the brief's explicit warning, no Cys fixed
  mod is written for the SCP rows; their `comment[modification parameters] = not available` (the
  PatternLab search-mod set for SCP is not documented; no variable mods stated).
- **Dissociation = HCD (beam-type CID).** Not stated in prose; **inferred** — the Orbitrap Astral
  performs HCD-only fragmentation for MS/MS, so this is instrument-intrinsic for an Astral DDA run.
  Flagged as an inference. **Collision energy** is not stated → column omitted (not fabricated).
- **Cleavage agent = Trypsin** (protocol: "digested with trypsin" / "trypsin digestion").

## 6. HeLa identity — parental HeLa, NOT HeLa-S3 (the brief's trap, considered and rejected)

The brief warns that a commercial 200 ng HeLa **digest** standard is Pierce **HeLa-S3** (CVCL_0058 /
EFO:0002791). Here the file is `BulkTrainHeLa200ngAstral.raw`, but the PRIDE protocol describes an
**in-house** preparation (lyse → DTT → IAA → trypsin), i.e. **not** a pre-digested commercial standard.
With only "HeLa cells" stated and an in-house digest, the defensible identity is **parental HeLa
(CVCL_0030 / EFO:0001185)**; "200ng" is the load amount, not a product SKU. HeLa-S3 was **not** asserted
(no evidence of the S3 subclone). OLS smart-mode for "HeLa" in CLO returned the wrong term
(`HeLa-MAGI-CCR5`, CLO:0037219 — a documented trap); parental HeLa was confirmed via EFO fuzzy search.

## 7. Column licensing & the `not applicable` traps (per-row template declaration)

`characteristics[cell line]`, `[cellosaurus accession]`, `[cellosaurus name]` in **cell-lines** forbid
both reserved words (`allow_not_available=false`, `allow_not_applicable=false` — the #35 B1 trap). Only
the HeLa row is a cell line. Solution (mirrors the approved PXD070185/PXD061710 pattern): the
**cell-lines** slot of `comment[sdrf template]` is written **per-row** — `NT=cell-lines;VV=v1.1.0` on the
HeLa row only, `not available` elsewhere (`comment[sdrf template]` is cardinality:multiple,
`allow_not_available=true`). Once a row is no longer governed by cell-lines, its `not applicable`
cell-line facets are legal. The **single-cell** slot is likewise per-row (only the 3 organoid rows), so
the 11 bulk rows carry `not applicable` in `single cell isolation protocol` / `cell identifier` /
`cells per well` legally (those columns are `allow_not_applicable=true` anyway).

- **`developmental stage`**: mouse = `not available` (age/stage not stated — not guessed); HeLa =
  `not applicable` (immortalized line); organoid = `not applicable` (in-vitro iPSC-derived; donor
  developmental stage is not a property of the deposited sample).
- **`age` = not available** (all rows; no donor/animal age stated; column disallows `not applicable`).
- **`sex`**: HeLa = `female` (CVCL_0030 donor); mouse = `not available`; organoid = `not available`

- **`comment[modification parameters]` (organoid) = not available** — see §5 (no Cys mod; search mods
  undocumented).
- **`characteristics[cell line]` (organoid) = not applicable.** WT83 is an iPSC line, but the deposited

## 9. Stated vs inferred

- **Stated (PRIDE description / protocols / paper):** Orbitrap Astral; DDA; label-free; trypsin; bulk
  HeLa + C57BL/6 kidney; DTT/IAA alkylation for bulk; **no** carbamidomethylation for single cells;
  WT83 brain-organoid single cells via **cellenONE**; 14 deposited raws.
- **Inferred (flagged):**
  1. **The 3 human organoid raws are single cells** (cells per well = 1). The description states
     "single-cell proteomics … cellenONE", the files map to the `SingleCell*.sepr2` search outputs, and
     one is named `SCP…`. **Caveat:** the files are large (123/218/390 MB) for single cells, and two are
     named `SSP…Organoid A/B`; there is **no deposited per-cell manifest**. cellenONE dispenses single
     cells, so `cells per well = 1` is the stated reading — but a reviewer should attack whether these
     could be small pools/whole-organoid single-shot runs.
  2. **The 10 mouse runs = one biological source (C57BL/6 kidney) with technical replicates 1–10**
     (`biological replicate = 1`). The description treats mouse as a single kidney-tissue source; the
     runs are numbered training injections. Whether they are one digest re-injected vs separate preps
     is **not deposited** → grouped as technical replicates; flagged.
  3. **`cell type` (organoid) = neural cell (CL:0002319, generic).** cellenONE isolation is image-based
     and cell-type-agnostic; **no raw→cell-type map is deposited.** Per the PXD071075 lesson and the
     PXD067623 precedent, a generic neural term is used rather than a specific neural subtype.
  4. **HCD dissociation** (§5) and **DDA** classification (instrument-intrinsic / stated).
  5. **`factor value[organism]`** — this training dataset has **no designed biological factor**; the one
     clean, fully-populated, ontology-backed axis is species (PRIDE keyword: *"Multi-species omics"*), so
     organism is used as the factor. The bulk-vs-SCP modelling split (the dataset's real purpose) is
     carried by `sample type` + `material type` + the per-row `single-cell` declaration, not the factor.

## 11. Validation (important `parse_sdrf` behaviour finding)

**`parse_sdrf validate-sdrf --template` is NOT a `multiple` option** (verified in
`sdrf_pipelines 0.1.5` source, `parse_sdrf.py:184`). When several `--template` flags are passed, click
keeps only the **last** one, so the file is validated against **a single template**, not the union.
(Sibling reports that pass `-t A -t B … -t F` were, in effect, validating only against template `F`.)
I therefore validated **each declared template separately, against the rows it governs**:

```
# full file — every row is governed by these:
parse_sdrf validate-sdrf -s annotations/PXD069898.sdrf.tsv -t ms-proteomics  → exit 0  "Everything seems to be fine."
parse_sdrf validate-sdrf -s annotations/PXD069898.sdrf.tsv -t human          → exit 0  "Everything seems to be fine."
parse_sdrf validate-sdrf -s annotations/PXD069898.sdrf.tsv -t vertebrates     → exit 0  (1 WARNING: strain "C57BL/6" not in NCBITaxon — accepted)
parse_sdrf validate-sdrf -s annotations/PXD069898.sdrf.tsv -t single-cell      → exit 0  "Everything seems to be fine."
# cell-lines governs ONLY the HeLa row (per-row declaration) → validate that subset:
parse_sdrf validate-sdrf -s <HeLa-row-subset>            -t cell-lines         → exit 0  "Everything seems to be fine."
```

The accepted **WARNING** is `strain "C57BL/6"` not resolving in NCBITaxon — `C57BL/6` is the correct,
stated strain designation (a `strain or breed` value, not a clean NCBITaxon label); kept rather than
downgraded to a reserved word. Validating the **full** file against `cell-lines` errors on the 13
non-cell-line rows' `not applicable` cell-line facets — this is **expected and correct**: those rows are
not governed by `cell-lines` (per-row declaration, §7). `parse_sdrf` exit 0 proves well-formedness only;
all ontology accessions in §4 were independently OLS-verified this run, not taken from the validator.
