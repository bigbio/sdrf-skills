## Findings

### B1 (blocker) — repeated `comment[data file]` across mixtures is not an acceptable encoding
- **Location:** `comment[data file]`, all 96 rows.
- **What is wrong:** only 16 distinct values (`H-HCT116-I8-1..16.wiff`) name 48 different physical runs, three per name (one per RAW zip, CRCs differ).
  - No standard column says which zip a file comes from. Only the producer's assay-name prefix carries that.
  - Extracting the zips into one folder overwrites files.
  - SDRF consumers key runs by data file.
- **Evidence:** I copied the SDRF and replaced `not available` precursor tolerance with `20 ppm`, to get past the accepted failure. `parse_sdrf convert-openms -t2` then fails with `ValueError: A SILAC channel occurs more than once in H-HCT116-I8-1.wiff`. That is a separate, structural failure. It also breaks the repo checklist item "file names in comment[data file] are unique per assay name" (validation.md). Precedent PXD009311 names .wiff members inside a zip, but it has no colliding names, so it does not license this.
- **Fix:** split into three SDRFs, one per RAW zip, with identical headers. For example `PXD007931-1stexperiment-MS.sdrf.tsv`, `-2ndexperiment-MS`, `-3rdexperiment-MS`.
  - Give each its own evidence manifest naming its zip and the embedded-name / MaxQuant-search mapping.
  - Keep biological replicate 1/2/3 and the content-based fractions.
  - Data file names are then unique within each file and map 1:1 to the zip they are extracted from.
  - Re-run validate / structure / reconcile on each. Run convert-openms with a substituted tolerance to show the duplicate error is gone.
  - Do not invent renamed file names (for example the assay name + `.wiff`). They would not exist in the deposit.

### m1 (minor) — provenance of the six 2017-09-13/14 re-runs in 2ndexperiment-MS.zip
- **What is unstated:** these files carry the `I 8_2_` prefix of the *other* mixture (3rd zip). The SDRF assigns them to exp2 because of the depositor's zip packaging and MaxQuant grouping (same search as the `I 8_` runs).
- **Evidence:** their content is modestly closer to the I 8_2 mixture than the genuine `I 8_` runs are.

  | Measure | Re-runs | Genuine `I 8_` runs |
  |---|---|---|
  | Jaccard excess (vs same I 8_2 fraction minus vs same 2016 fraction) | +0.017..+0.090 (mean +0.065) | +0.004..+0.026 |
  | Robust SD of per-peptide log2 H/L difference vs the I 8_2 mixture | 0.111 | 0.124 |

  The signals that would fingerprint a mixture (median raw H/L, Pro-conversion delta) do not separate the mixtures. This is therefore not decisive, and I accept the assignment.
- **Fix:** add a manifest limitation saying so.

### m2 (minor) — companion files are not recorded
- **What is missing:** AB Sciex companions are not recorded as `comment[associated data file]`.
- **Detail:** the names are inconsistent. The 1st and 2nd zips and 3rd-zip members 1–2 use `.scan`; 3rd-zip members 3–16 use `.wiff.scan`. Readers need `.wiff.scan`.
- **Fix:** optionally add the column and note the naming in the limitations.

### m3 (minor) — wording in the manifest
- **What is inaccurate:** "identical member names" holds only for basenames. The full paths differ: `1st experiment/`, `2nd experiment-MS/2nd experiment/`, `3rd experiment-MS/3rd experiment/`.
- **Fix:** reword it.

### m4 (minor) — online check result not recorded
- **What is missing:** validation.txt records only `check --offline`.
- **Fix:** add the online run and the UNIMOD:28 refutation.
