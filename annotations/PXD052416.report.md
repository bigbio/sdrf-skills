## Key decisions and evidence

**Two cell lines, not one.** The 88 single cells are ATCC parental HeLa (`EFO:0001185` /
`CVCL_0030`). The 30 QC runs are **HeLa-S3** (`EFO:0002791` / `CVCL_0058`) — a distinct clonal
derivative with its own Cellosaurus entry. Neither the paper ("HeLa digest") nor PRIDE ("Pierce
HeLa protein Digest") says S3; Thermo's page for cat. 88328 does: the standard "originates from a
well-established HeLa S3 reference cell line". Caught by review — the parental line was the
plausible, validator-clean, wrong answer.

**Replicate structure.** All 30 QC runs are injections of *one* commercial vial → `biological
replicate = 1`, technical replicates numbered within each (amount × gradient) group. This
reproduces the paper's own Fig. 3C design exactly (10 × 200 pg, 5 × 10 ng) — a cross-check only
visible once the structure was right. Each of the 88 single cells is a distinct biological
replicate.

**Cleavage agents.** Trypsin + Lys-C on all 118 rows. Single cells: "2.5 ng/2.5 ng Trypsin/LysC"
(paper). QC: Thermo states the standard is manufactured with LysC and Trypsin. Correct for both
groups for different reasons; the search specified trypsin only, but this column describes
digestion.

**Modifications.** `Oxidation` (UNIMOD:35, TA=M) and `Acetyl` (UNIMOD:1, `PP=Protein N-term`) —
both variable. No Carbamidomethyl: the protocol has no reduction/alkylation step. PRIDE's
`modifications` field says "No PTMs are included in the dataset", contradicting the paper's
Methods; the peer-reviewed Methods were followed.

## Values deliberately left `not available`

| column | rows | why |
|---|---|---|
| `comment[isolation window width]` | all | diaPASEF windows are **variable-width**. Extracted from the deposited `analysis.tdf`: 15 windows, 15 distinct widths, 29.52–74.51 m/z. The column's pattern is `^\d+(\.\d+)?$` — a single scalar — so no legal value is correct. The naive derivation from the paper ("15 windows spanning 400–1000" → 40 m/z) is **not one of the 15 real widths** and would pass validation. See issue #33. |
| `characteristics[genotype]`, `[culture medium]` | QC rows | Genotype of the commercial standard is not stated; Thermo does not publish its culture conditions. |

`comment[scan window lower/upper limit]` = 400 / 1000 from the paper's stated method. The
measured window edges in `analysis.tdf` are 402.5–1015.0; the paper's figures are the stated
design and are what the column documents.

## Reviewer findings (4 minor, none blocking)

1. `comment[proteomics data acquisition method]` / `comment[dia method]` carry bare labels without
   accessions, though `PRIDE:0000450` / `PRIDE:0000650` exist. The `dia-acquisition` template's
   own `values` validator mandates the literal string, so this is the template's requirement, not
   an omission — but it is inconsistent with `comment[label]` in the same file.
2. `characteristics[cellosaurus accession]` rows 1–88 use parental `CVCL_0030` for CRISPR ATG5-KO
   clones. No Cellosaurus entry exists for in-house clones; `characteristics[genotype]`
   disambiguates.
3. Absent recommended columns: `ancestry category`, precursor/fragment mass tolerance (DIA-NN
   selected fragment tolerance dynamically per file, so no fixed value exists), `ms1 scan range`.
4. QC group uses four source names split by gradient length. Gradient length is an acquisition
   property rather than a sample property, so `..._10min` and `..._20min` are arguably the same
   sample. Internally coherent; flagged as defensible rather than clearly right.
