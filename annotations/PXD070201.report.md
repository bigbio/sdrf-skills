## Correction (post-review)

An independent review flagged three defects. All three were re-investigated from **primary sources**
(the deposited Spectronaut v19.8 search config inside `Search_Result.zip`, the Research Square preprint
Methods, and Thermo `.raw` headers range-read from the PRIDE ZIP bundles) and corrected as follows.

### 1. Carbamidomethyl added to vendor-digest standard/reference rows (BLOCKER — fixed)
**Primary evidence.** Inflated the `…ExperimentSetupOverview…` config from `Search_Result.zip` for the
Hela250pg, HKHPp1p2, and RAWHPp3p4 Spectronaut projects (HTTP range-read + deflate). All three declare,
verbatim:
> `Fixed Modifications:: Carbamidomethyl (C)` · `Variable Modifications: Acetyl (Protein N-term), Oxidation (M)`
This matches the paper Methods ("including fixed carbamidomethylation and variable modifications such as
protein N-terminal acetylation and methionine oxidation"). So the search **did** use fixed CAM.

**Why the original uniform omission was half-right.** The single cells use documented one-pot **in-well
Trypsin/Lys-C digestion with no reduction/alkylation step** (paper Methods; grep of full text finds no
DTT/TCEP/iodoacetamide/chloroacetamide). Their cysteines are genuinely unmodified, so a fixed-CAM search
setting does **not** reflect their real chemistry — CAM correctly stays **off** the 697 single cells.

**What was wrong.** The vendor-prepared commercial digests **are** reduced + alkylated at the factory and
were then searched with fixed CAM, so their cysteines **are** carbamidomethylated:
- **Pierce™ HeLa Protein Digest Standard** (ThermoFisher Ref# 88329) — the 704 `standard` rows (250 pg / 5 ng
  / 10 ng / QC / CarryOver). Vendor documentation: *"fully reduced, alkylated (iodoacetamide), and desalted
  after trypsin digestion."*
- **Promega MS-Compatible Human (K562) Digest** (V6951) — the 40 `reference` rows whose source name contains
  `K562` (`HKHPp2_K562_lib` ×20 + `SQp5_K562_10ng` ×20). Vendor documentation: *"reduced with DTT and
  alkylated with iodoacetamide, then digested with Trypsin/Lys-C."*

**Fix (744 rows total).** Added a third `comment[modification parameters]` column
`NT=Carbamidomethyl;AC=UNIMOD:4;TA=C;MT=Fixed` (Fixed; per-mod, `cardinality: multiple`; ordered CAM →
Oxidation → Acetyl), populated **only** on those 744 vendor rows and set to `not applicable` on the other
756 rows — the same per-arm asymmetry as the approved `PXD069335`. On the same 744 rows set
`comment[reduction reagent]=NT=Dithiothreitol (DTT);AC=PRIDE:0000608` and
`comment[alkylation reagent]=NT=Iodoacetamide (IAA);AC=PRIDE:0000599`.

**Deliberately left WITHOUT CAM (in-house material, no documented alkylation):** the 697 single cells and
the 39 in-house RAW 264.7 bulk references (`RAWC3` ×19 + `RAWL1` ×20 — no commercial LPS-stimulated RAW
digest exists, so these are lab-prepared; the paper documents no alkylation for any in-house prep). Per
ANNOTATOR_BRIEF ("never assert Carbamidomethyl without a documented alkylation step").
`UNIMOD:4 = Carbamidomethyl`, `PRIDE:0000608 = Dithiothreitol (DTT)`, `PRIDE:0000599 = Iodoacetamide (IAA)`
all verified live via OLS this run.

**Round-2 correction (the `Hela_lib` residual, now RESOLVED against the first pass):** a second independent
review resolved the residual flag below from the primary text. The 20 `Hela_lib` rows (`…_Hela_lib_…
DIAwet5ng/10ng`, lines 1005–1024) are the **commercial Pierce HeLa Protein Digest Standard (88329)**, not
in-house cultured HeLa: the deposited Methods describe Pierce 88329 dilutions "at 10 ng/µL and 5 ng/µL **for
library creation**" as the only HeLa digest material, and the parallel `K562_lib` rows (same `HKHPp2` plate,
same `_lib`/`DIAwet5ng` naming) were already annotated commercial. They were therefore corrected to match the
704 Pierce standard rows: **cell line → HeLa S3 `CVCL_0058` / `CLO:0003695`, cellosaurus name → HeLa S3**, and
**Carbamidomethyl (Fixed) + DTT + Iodoacetamide added** (vendor reduced/alkylated material, searched with the
deposited fixed-CAM setting). CAM-bearing rows are now **764** (704 Pierce standard + 40 K562/Promega +
20 Hela_lib Pierce); HeLa-S3 rows now **724**, parental HeLa **199**. Re-validated → exit 0.
`factor value[cell line]` was also updated to `HeLa S3` on the same 20 rows so it mirrors the corrected
characteristic (a third review caught that the factor column had been left stale at `HeLa`).

### 2. Single-cell isolation protocol enum corrected (fixed)
`characteristics[single cell isolation protocol]` was `droplet microfluidics` on the 697 single-cell rows.
The Tecan UNO performs HP thermal-inkjet **microfluidic digital dispensing** (free-flying pL drop-on-demand),
which is **not** droplet microfluidics (water-in-oil emulsion), piezo (cellenONE), or acoustic ejection.
The `single-cell` template enum for this column is `fixed: FACS, cellenONE, microfluidics, laser capture
microdissection, manual picking, nanoPOTS, droplet microfluidics, acoustic droplet ejection`. Changed the
697 rows to the most accurate legal value **`microfluidics`**.

### 3. CarryOver instrument re-checked — original value CONFIRMED (no change)
The paper assigns the *carryover-evaluation experiment* to an Orbitrap Exploris 480, which prompted the
review. I HTTP-range-read the first 256 KB of the deposited CarryOver `.raw` headers (inflated from
`LL2092_250pg_wet.zip`) for **both** CarryOver subtypes — `Helaiib_CarryOvertest…DIAwet5ng.raw` and
`HelaQC_CarryOvertest1…DIAwet.raw`. Both headers report **`Orbitrap Astral`** (instrument codename
`TNG-Merkur` = Astral); the string `Exploris` is absent. Raw header beats Methods prose, so the deposited
CarryOver runs stay **`NT=Orbitrap Astral;AC=MS:1003378`**. The Exploris 480 carryover assessment described
in Methods was evidently not part of the deposited CarryOvertest runs.
