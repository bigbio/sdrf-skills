## Study

Booster/carrier-based multiplexed scMS (TMTpro 16-plex) applied to **OCI-AML8227**, a primary
patient-derived AML culture that retains a leukemic hierarchy (LSC → progenitor → blast).

## Annotatable — the channel → sample map is deposited

This is the **inverse** of the `PXD043473` failure mode in `BLOCKED.md`. The deposit contains
`SCeptre_FINAL.zip` (981 MB), which ships the complete per-channel key:

| source | content |
|---|---|
| `data/<plate>/label_layout*.txt` | well → TMTpro channel, per 384-well plate |
| `data/<plate>/sort_layout*.txt` | well → FACS-sorted population (BLAST / PROG / LSC / BULK / empty) |
| `data/<plate>/sample_layout*.txt` | well → which of the 24 MS runs (plate **column** = one run) |
| `data/<plate>/file_sample_mapping.txt` | raw file → plate + run |
| `results/<dataset>/meta.txt` | **one row per (file × channel)** with well, sorted population, FACS-gated population, and per-cell FSC/SSC/CD34/CD38 |

The zip was read **without downloading it** — PRIDE's HTTPS mirror honours HTTP range requests, so
the zip central directory was fetched and only the layout/meta members (a few hundred KB) were
extracted. `Abundances Normalized F1 127N Sample BLAST`-style headers in
`data/library/library_MS3_Proteins.txt` confirm Proteome Discoverer sample names were set here — the
`"Sample, n/a"` default that blocks PXD043473 does **not** occur.

**Independent round-trip check:** the SDRF was rebuilt from `label_layout.txt` + `sort_layout.txt` +
`file_sample_mapping.txt` (a different code path from the `meta.txt` used to generate it) — 336/336
channels of the `500ms` plate agree, 0 mismatches.

## Templates

`ms-proteomics v1.1.0`, `human v1.1.0`, `single-cell v1.0.0`, `clinical-metadata v1.0.0`.

`clinical-metadata` is declared **solely** to license `characteristics[phenotype]`, which carries the
experimental factor (differentiation stage). It adds no required column that was not already present
(its only required addition, `disease`, is already there).

**`cell-lines` is deliberately NOT declared.** OCI-AML8227 is a primary patient-derived AML culture,
not an immortalised line, and **has no Cellosaurus entry** (verified live: `OCI-AML8227`, `AML-8227`,
`8227`, `OCI-AML 8227` and `id:OCI-AML*` all return `numFound: 0`; the API is working — `OCI-AML3`
returns 5 hits). `cell-lines/1.1.0` makes `characteristics[cellosaurus accession]` **required**, so
the template is not declarable even if it were biologically apt.

> **Trap:** `python -m tools cellline lookup OCI-AML8227` confidently returns
> **OCI-AML2 / CVCL_1619 at 0.82 "confidence"** via fuzzy match. OCI-AML2 is a *different*,
> immortalised cell line from a different patient. Taking that value would have asserted the wrong
> donor, disease detail and Cellosaurus accession on all 4050 rows, and it would have validated
> cleanly. This is the offline-map false-positive the brief warns about.

### The 15 excluded runs — no deposited channel → sample map

These are the only runs where the PXD043473 blocker actually applies, and it applies **locally**:

- **12 CV-check runs** (`..._CVcheck_{150,300,500,1000}ms_{1,2,3}.raw`). Per the paper, twelve
  single-cell samples were **pooled into one aliquot** which was then injected in triplicate at four
  injection-time settings. Each TMTpro channel of that aliquot therefore holds **12 different single
  cells** pooled together, and **no layout for the CV plate is deposited** (`data/cv/` contains only
  `cv_InputFiles.txt` and `cv_Proteins.txt`; the latter's headers are bare
  `Abundances Grouped F1 126` with no sample names). The per-channel differentiation-stage
  composition is therefore unrecoverable. *(That such an assignment existed is implied — Fig. 2d
  reports LSC n=15 and blast n=12, i.e. 5 LSC × 3 and 4 blast × 3 replicates — but **which** channel
  held which stage is not deposited, and the label layouts are randomised per plate column, so it
  cannot be reconstructed.)*
- **3 `celltype_booster` runs.** Supplementary Fig. 2's caption says "**The 1:1:1 booster** was
  measured … without the addition of other channels", but the filenames say `celltype_booster`
  (i.e. the cell-type-specific pools). The three raws share one
  `originalRawFileNameWithoutExtension` (sequence rows 8/22/36 — three injections of one sample), the
  `booster_only.ipynb` notebook plots only `F1`, and no deposited table maps `F1/F2/F3` to filenames.
  Which pool each run holds is therefore not established.

Annotating either group would mean inventing channel identities — exactly what `BLOCKED.md` exists to
prevent. They are recorded there as a **partial**-scope exclusion, not a dataset-level block.

## Key decisions and evidence

**Instrument, determined per run — not assumed.** PRIDE lists two instruments. Proteome Discoverer's
`*_InputFiles.txt` inside `SCeptre_FINAL.zip` carries a per-file `Instrument Name`: all **276** files
it covers say `Orbitrap Exploris Slot #0085`. The remaining **13** were resolved by HTTP-range
reading the first 256 KB of each `.raw` and decoding utf-16-le: the **10 MS3 library fractions are
`Orbitrap Fusion`**, the 3 `celltype_booster` runs are `Exploris 480`. Every file was checked
individually. This matches the Methods (scMS on Exploris 480; MS3 bulk on Orbitrap Fusion Tribrid).
Note the Methods also describe a **Q-Exactive HF-X** lysis-buffer comparison — **no HF-X file is
deposited**, and the 289 raws are fully accounted for as 279 Exploris + 10 Fusion.

**The carrier is a distinct sample and is annotated (264 rows).** Omitting it is the classic error.
Its composition is resolved per plate from **Supplementary Table 1** (`Datasets generated in this
study`) and **Supplementary Fig. 7c** ("`bulk_c` contains 1:1:1 booster, `bulk_b` contains 'bulk'
booster, `bulk_b_e` contains bulk booster and empty wells"):

| plate group | carrier (126) | reference (127N) | single-cell channels |
|---|---|---|---|
| `300ms`, `500ms` | 1:1:1 | — (127N **is a single cell** here) | 14 |
| `bulk_c` ×3 | 1:1:1 | ✔ | 13 |
| `bulk_b` ×3 | bulk | ✔ | 13 |
| `bulk_b_e` ×2 | bulk | ✔ | 12 + 1 empty |
| `enriched` | bulk | ✔ | 13 |

The reference channel is annotated as the **same composition as its plate's booster** — stated in the
paper: "we used the 127 N channel for a reference channel containing a 10-cell equivalent with the
same composition as the booster".

**127N is not a fixed role.** In `300ms`/`500ms` it carries a real single cell; in the six bulk
plates and `enriched` it is the reference. The SDRF is driven off the deposited `Well` field rather
than the channel name, so this is handled per row rather than by a rule that would have been wrong
for 672 rows.

**127C is emitted for no run.** "The 127 C channel is left empty due to isotopic impurity
contaminations from the 126 booster channel" — no TMTpro-127C reagent was ever added, so there is no
sample. This is distinct from the 48 `empty` rows in `bulk_b_e`, which are wells that were fully
labelled and pooled but received **no cell** — a deliberate negative control ("we introduced empty
wells … to investigate our ability to detect them in SCeptre"). The `single-cell` template's
`characteristics[cell identifier]` has `empty` as an explicit special value, so — unlike the
`cell-lines` wall that cost `PXD052416` its 14 blanks — these rows are expressible and are kept.

**Modifications.** From the Methods: TMTpro fixed on K and peptide N-term, Carbamidomethyl fixed on
C, Oxidation (M) and Acetyl (protein N-term) variable.
`NT=TMTpro;AC=UNIMOD:2016` — **not** UNIMOD:737 (TMT6plex), which is the wrong reagent for this
study. `UNIMOD:1 = Acetyl` (verified live), placed in `PP=Protein N-term`, **not** `TA=`.
PRIDE's `modifications` field lists only "monohydroxylated residue, iodoacetamide derivatized
residue" (Oxidation + Carbamidomethyl) — it **omits TMTpro and Acetyl entirely**, i.e. it omits the
reagent the whole study is built on. The peer-reviewed Methods were followed.

**Per-cell FACS index data is annotated.** `characteristics[forward scatter]`,
`[side scatter]` and `[enrichment marker]` (`CD34:APC-Cy7-A=<v>;CD38:PE-A=<v>`) are populated from
the deposited `meta.txt` for all 3432 single cells — 0 missing values. `characteristics[phenotype]`
uses the deposited **`Gated Population`** (the paper's own FlowJo gating, which subdivides blasts
into CD38+/CD38−), not the coarser sort gate.

**`characteristics[cell type]` = `NT=acute myeloid leukemia cell;AC=BTO:0001545`** (exact OLS match)
on every sample-bearing row. CL has **no** term for leukemic blast / leukemic stem cell / leukemic
progenitor; smart-mode OLS offers `hematopoietic stem cell (CL:0000037)` for "leukemic stem cell" and
`CL:0001024` (CD34+CD38− **hematopoietic** stem cell) for the LSC immunophenotype. Both were
**rejected**: they assert a *normal* haematopoietic identity for leukemic cells and would have
validated cleanly. The differentiation stage instead lives in `characteristics[phenotype]` /
`factor value[phenotype]` with the defining immunophenotype spelled out.

**`characteristics[cells per well]`** is read as *cells represented by this channel in this run*:
`1` single cell, `0` empty, `200` carrier (200-cell equivalent loaded; the booster **well** held 500),
`10` reference, `20000` MS3 library channel. Stated here because the well-vs-channel reading is a
genuine ambiguity in the column's wording.

## Values deliberately left `not available` / `not applicable`

| column | rows | why |
|---|---|---|
| `characteristics[organism part]` | all | OCI-AML8227 is a *cultured* patient-derived model; the Methods never state the donor's tissue of origin (bone marrow vs peripheral blood). Not guessed. |
| `characteristics[age]`, `[sex]`, `[ancestry category]` | all | Donor demographics are not reported anywhere in the paper, PRIDE, or the supplement. `human` requires age/sex but permits `not available`. |
| `comment[precursor/fragment mass tolerance]` | all | Methods say only "Default settings were applied" (PD 2.4) / "standard settings of the Tribrid TMTpro SPS MS3 workflow". The numeric defaults were **not** written in — they are not stated evidence. |
| `characteristics[phenotype]` | 48 empty rows | `not applicable` — the well has no cell. |
| `comment[reference channel]` | `300ms`, `500ms` | `not applicable` — those plates have no reference channel (Suppl. Table 1). |

## Known limitations / flagged for review

1. **`comment[dissociation method]` is single-valued but the MS3 runs use two.** The 90 MS3 library
   rows declare `HCD` + `60% NCE` (the SPS-MS3 scan that produces the TMTpro reporter ions and hence
   the deposited quantification). Their **MS2** stage is in fact **CID at 32% NCE in the ion trap**.
   The column cannot express both. `comment[collision energy]`'s pattern *does* permit `32% NCE;60% NCE`,
   so the two columns disagree in expressive power. Flagged as arguably-defensible, not clearly right.
2. **`comment[facs sorting mode]` omitted.** The template enum is
   `single cell | purity | yield | 4-way purity`. The single cells are `single cell`, but the booster
   and MS3 wells were sorted in **"three-way purity"**, which the enum cannot express. Rather than
   round it to `purity`, the optional column was dropped. Spec gap.
3. **`characteristics[phenotype]` is free text.** Its validator is `ontology(pato, efo)` at
   *warning* level with "or free text" permitted. No PATO/EFO term captures "blast (CD34− CD38+)".
4. **Two runs are named `_faulty`** (`bulk_b_P3_S16`, `bulk_c_P1_S23`). Both are annotated: each is
   the **only** deposited run for its plate column, both carry a complete well map in `meta.txt`, and
   each plate still has exactly 24 runs. The submitter's QC opinion is not encoded in the SDRF.
5. `characteristics[individual]` = `OCI-AML8227` on all rows — every cell derives from the single
   donor of this model. The literal donor identifier is not published.
6. **Deposited ≠ analysed.** 3432 single cells are annotated; the paper's figures use QC-filtered
   subsets (e.g. 2025 of the 2448 bulk-plate cells). The SDRF describes what was *acquired*.
