## Study

Global absolute quantification of single *Xenopus laevis* fertilized eggs — at the time the largest
single-cell proteome (5837 proteins). Compares single eggs against stage-10.5 gastrula embryos, and
the single-cell proteome against the matched transcriptome.

| | |
|---|---|
| Publication | PMID:25056316 / PMC4150773 / doi:10.1093/nar/gku661 (open access, full text + supplement read) |
| Instruments | **LTQ Orbitrap Velos** (9 runs) and **Q Exactive** (55 runs) — verified per file, see below |
| Labelling | label free (59 runs) + **triplex dimethyl** (5 runs × 3 channels) |
| Search | MaxQuant 1.3.0.5, Trypsin/P, iBAQ, UPS2 spike-in for absolute quantification |
| Screen row | `include` — `label free`, `n_single_cells=5` |

**Organism is *Xenopus laevis* (NCBITaxon:8355), an amphibian — `vertebrates`, never `human`.**

## Scope: 64 deposited raw files → 74 rows, 15 source samples

Every deposited raw file is annotated. **64/64 used, zero orphans in either direction** — asserted
programmatically in the build script against the authoritative REST file list

The deposition is **four distinct sub-experiments**, which the PRIDE record does not separate:

| set | figure | files | rows | instrument | sample |
|---|---|---|---|---|---|
| A unfractionated triplicates | Fig 1 | 9 | 9 | LTQ Orbitrap Velos | 3 single eggs × 3 technical replicates |
| B deep proteome, eggs | Fig 2–4 | 25 | 25 | Q Exactive | 5 single eggs × (1 iBAQ + 4 SAX) |
| C deep proteome, embryos | Fig 4 | 25 | 25 | Q Exactive | 5 gastrula embryos × (1 iBAQ + 4 SAX) |
| D triplex dimethyl | Fig S2 | 5 | 15 | Q Exactive | 2 single eggs × 3 channels × 5 SAX fractions |

Row count: 9 + 25 + 25 + (5 × 3) = **74**. The 15 source samples are 3 + 5 + 5 + 2 single
eggs/embryos; each is a distinct biological specimen from a separate collection (different dates,
separate sub-experiments), so egg identities are **not** shared across sets — hence the
`egg_velos_*` / `egg_deep_*` / `egg_dimethyl_*` / `embryo_deep_*` naming rather than reusing the
paper's colliding "Egg 1–3" / "Egg 1–5".

## Why this dataset was annotatable — including the multiplexed part

Set D is triplex dimethyl and therefore needed a channel → sample map, or it would have been
BLOCKED. **The map exists, but only as a figure, not as text.** The Methods say merely "each sample
was differentially labeled ... Differentially dimethyl labeled samples were mixed" — naming no
samples. Supplementary **Figure S2**'s workflow diagram was rendered as an image and read directly:

- **egg A** → two separate FASP digests → **Light** + **Medium**, enclosed by the grey
  "Technical variation" ellipse
- **egg B** → one FASP digest → **Heavy**; the red "Biological variation" ellipse spans
  Medium + Heavy
- → Combine → SAX → "5× 4h gradients" — matching the 5 deposited dimethyl fractions exactly

This is corroborated by the deposited `Dimethyl_labeling_txt/summary.txt`: `Multiplicity 3`,
`Labels0 = DimethLys0;DimethNter0`, `Labels1 = DimethLys4;DimethNter4`,
`Labels2 = DimethLys8;DimethNter8` — the Boersema triplex the paper cites (ref 36). So Light/Medium
are two digests of one egg (technical replicate 1 and 2 of `egg_dimethyl_A`) and Heavy is a second
egg (`egg_dimethyl_B`). **No channel identity was fabricated.**

`comment[label]` uses `DIMETHYL0` / `DIMETHYL4` / `DIMETHYL8` (PRIDE:0000848 / :0000850 /
:0000852), which map one-to-one onto MaxQuant's Lys0/4/8. This vocabulary is not decorative —
mutation-testing proved `parse_sdrf` **errors** on a bogus PRIDE label term, so these three
accessions were genuinely validated.

## Key decisions and evidence

**Instrument — verified from all 64 raw file headers, not trusted from PRIDE.** PRIDE's
`instruments` field lists both `LTQ Orbitrap Velos` and `Q Exactive` without saying which file is
which. Each of the 64 files was HTTP-range-read (first 256 KB, decoded utf-16-le) and the model
grepped: **exactly the 9 `20130716_*` files are Velos; the other 55 are Q Exactive** — a clean
partition matching the paper ("data of Figure 1 and Supplementary Figure S1" on the Velos, "data of
Figures 2–4" on the Q Exactive). PRIDE is correct here but unallocated; the paper and the headers
agree.

**The instrument methods embedded in the raw headers independently confirm the paper.** This is
directly extracted, not inferred:

| | Velos (set A) | Q Exactive (sets B/C/D) |
|---|---|---|
| MS1 | `FTMS + p norm o(300.0-1650.0)` | Full MS, R=70,000, 300–1650 |
| MS2 | **`ITMS`** (ion trap) | dd-MS2, R=17,500, Orbitrap |
| activation | `Activation Type: CID` | HCD |
| collision energy | `Normalized Coll. Energy: 35.0` | `NCE 25.0`, Stepped NCE off |
| top-N | *"Scan Event 2 repeated for **top 15** peaks"* | `TopN 10` |

Both top-N values match the paper's "top 15" (CID) and "top 10" (HCD) exactly. This is what fixes
the fragment tolerance below.

**Digestion enzyme came from the deposited search, because the paper never states it.** The Methods
say only "digested using filter-aided sample preparation (FASP)" — no enzyme. Rather than assume
trypsin, `summary.txt` was range-read out of the deposited MaxQuant archives: `Protease = Trypsin/P`
on every one of the 55 Q Exactive runs. Annotated `NT=Trypsin/P;AC=MS:1001313` (the /P variant,
not plain Trypsin MS:1001251).

**UPS2 spike is in the iBAQ runs only — not in the SAX fractions.** Figure S1B's workflow shows the
whole-cell lysate split **1/10 → +1 µg UPS2 → "iBAQ sample"** and **9/10 → "SAX sample"** (four
fractions). PRIDE's `sample_processing_protocol` states flatly that UPS2 "was spiked into the
sample", which would wrongly imply all runs. The 1:4 UPS2:sample ratio in the Methods is consistent
with 1 µg into a 1/10 aliquot. Corroborated by the FASTA lists in `parameters.txt`: both label-free
searches include `ups1_ups2_sequences.fasta`, and the **dimethyl search does not** — dimethyl is
relative quantification with no spike. So `characteristics[spiked compound]` is UPS2 on the 10 iBAQ
rows and `not applicable` on the 40 SAX + 15 dimethyl rows.

**The iBAQ run is not a fraction of the SAX series.** For each deep-set sample the two branches are
separate aliquots with different preparation, and MaxQuant itself treats them as separate
experiments (`Egg_1_iBAQ` vs `Egg_1_SAX` in `summary.txt`). Encoded as
`comment[technical replicate]` 1 = iBAQ branch (fraction 1, `fractionation method = not
applicable`) and 2 = SAX branch (fractions 1–4, SAX). This keeps every
(source, technical replicate, fraction, label) key unique — asserted in the build script, 0
duplicates — which a naive "iBAQ = fraction 1, FT = fraction 1" encoding would have violated.

Fraction identifiers follow SAX elution order: FT=1, pH11=2, pH8=3, pH2=4 (deep set), and
FT=1, pH11=2, pH8=3, pH5=4, pH2=5 for dimethyl (the paper: SAX "with the addition of an extra
elution fraction at pH5" — exactly the 5 deposited dimethyl files).

**Cell type / material type carry the single-cell claim.** A fertilized egg 60 min post-fertilization
is uncleaved and one-celled — the paper calls it a "stage 1 embryo". So egg rows are
`cell type = zygote` (**CL:0010017** — verified live; the plausible-looking CL:0000365 is *not* the
zygote term, and guessing it would have been silent corruption), `material type = cell`,
`sample type = single cell`, `cells per well = 1`. Gastrula 10.5 embryos are thousands of cells:
`material type = whole organism`, and the single-cell-specific fields are `not applicable`.

**Developmental stage is the factor.** `fertilized egg stage` (EFO:0001322) vs `gastrula stage`
(UBERON:0000109, in EFO) — the egg-vs-embryo contrast of Figure 4, the only group comparison in the
deposition. TERMS.tsv restricts this column to EFO; both terms resolve within EFO. Xenopus
Nieuwkoop–Faber stages live in XAO, which the column does not permit, so NF stage 10.5 is recorded
in this report rather than forced into the cell.

## Values deliberately left `not available` / `not applicable`

| column | value | why |
|---|---|---|
| `characteristics[organism part]` | `not applicable` | Neither a whole egg nor a whole embryo is a *part* of an organism — nothing was dissected. UBERON offers no term for an undissected whole Xenopus egg (search returns egg chorion / eggshell / egg yolk / shelled egg — all wrong). `allow_not_applicable=true`. `material type` + `developmental stage` carry the information instead. |
| `characteristics[sex]` | `not available` | Rows describe the **embryo/zygote**, not the mother. Sex is genetically fixed at fertilization but was never determined, and at gastrula it is not observable. The donor female's sex is not the sample's sex — annotating `female` would be a category error. |
| `characteristics[strain or breed]` | `not available` | No strain stated anywhere; *X. laevis* females were simply hCG-injected. |
| `characteristics[precursor mass tolerance]` | `not available` | **Not recoverable.** MaxQuant 1.3.0.5's `parameters.txt` does not record first/main-search precursor tolerance, and no `mqpar.xml` was deposited. The paper says only "default settings". Asserting MaxQuant's 20 ppm first-search / 6 ppm main-search defaults would be an assumption about an undocumented setting, so it is abstained from. |
| `characteristics[spiked compound]` (set A) | `not available` | The 9 Velos runs have **no deposited search output** (below), so the spike is undocumented — despite `IBAQ` in the filename. |
| single-cell columns (embryos) | `not applicable` | A gastrula embryo is not a single cell. |
| `sample type` (embryos) | `not applicable` | PRIDE:0000895 has only 5 children (`single cell`, `multiplex sample`, `standard`, `environmental sample`, `Quality Control Sample`). TERMS.tsv's `values` prose additionally advertises `study sample`, `bulk control` etc., but **no such PRIDE class exists** — a case of `values` being prose rather than a closed grammar. Nothing fits a bulk embryo. |

`characteristics[disease] = normal` for all rows (healthy, unmanipulated embryos).

## Conflicts found and how they were resolved

**1. PRIDE `modifications` vs the searches — no conflict; they corroborate.** PRIDE lists
"monohydroxylated residue", "acetylated residue", "iodoacetamide derivatized residue". Both deposited
`parameters.txt` say Carbamidomethyl (C) fixed; Oxidation (M) + Acetyl (Protein N-term) variable.
These are the same three. Annotated as `NT=Carbamidomethyl;AC=UNIMOD:4;TA=C;MT=Fixed`,
`NT=Oxidation;AC=UNIMOD:35;TA=M;MT=Variable`,
`NT=Acetyl;AC=**UNIMOD:1**;PP=Protein N-term;MT=Variable` — Acetyl is UNIMOD:1, verified live, *not*
the UNIMOD:21 (Phospho) swap. The positional value `Protein N-term` is in `PP=`, never `TA=`.

**2. `3Eggs3Replicates.zip` does not describe the files its name implies.** Its `summary.txt` lists
**45 runs that were never deposited** — `20131213_Velos1_*_pool1/2/3_*` (the Fig S1B pooled-egg
technical replicates), `20131216_Velos1_*_SingleEgg1/2/3_*` and `20131220_Velos1_*_Embryo1/2/3_*`,
each SAX-fractionated. Conversely, **the 9 deposited `20130716_*` raw files appear in none of the
three deposited result archives** (`grep` count: 0 in all three). So:

- the zip's search results ↔ raw files: **not deposited**
- set A's raw files ↔ search results: **not deposited**

This is a genuine gap in the deposition, not an annotation error. It is why set A's tolerances and
spike are treated as paper-derived or `not available` rather than read from a search. It also means
the zip name is misleading: it is *not* the "3 eggs × 3 replicates" of Figure 1.

**3. Europe PMC's `supplementaryFiles` endpoint is contaminated.** For PMC4150773 it returns
`mmc1.pdf`–`mmc10.xlsx`, `fx1.jpg`, `gr1–gr6.jpg` — **supplementary files of an unrelated Cell-press
paper** — alongside the genuine `supp_gku661_*` and `gku661fig*` files. `S11.xlsx`/`S12.xlsx` are
1817-byte non-zip stubs. Only the `gku661`-prefixed files were used. A curator trusting `mmc2.xlsx`
here (the very filename that *was* the real per-sample table in PXD023366) would annotate from the
wrong paper entirely.

**4. `parse_sdrf` requires factor value columns last**, contradicting `skills/sdrf-annotate/SKILL.md`
Step 3, which places `factor value[...]` before the `comment[sdrf version]` / `comment[sdrf template]`
block. Following the skill's order produced
`ERROR: The following factor column should be last`. The file follows the validator (and the
`spec/examples/` convention).

## Stated vs inferred

**Directly evidenced** (paper Methods, supplementary figures, deposited `summary.txt` /
`parameters.txt`, or raw file headers): organism; egg/embryo identity and counts; developmental
stages; instrument per file; CID/HCD; NCE 35/25; top-15/top-10; MS2 analyzer; Trypsin/P; the three
modifications; SAX fractionation and fraction count; UPS2 placement; the dimethyl channel map;
all 64 filenames.

**Inferred — flagged for the reviewer:**

1. `characteristics[single cell isolation protocol] = manual picking` for all egg rows. The paper
   never names an isolation method. Evidence: *X. laevis* eggs are ~1.2 mm and macroscopic; each was
   "collected in an independent tube, snap-frozen", then "thawed and homogenized in 15 µl" — purely
   manual handling, with no FACS, microfluidics, cellenONE, LCM or nanoPOTS anywhere in the paper.
   `manual picking` is the only enum member not contradicted by the evidence. Note this column
   permits `not available` here (unlike PXD023366, where `allow_not_available=false` forced the
   choice), so this is a deliberate, contestable call rather than a forced one.
2. `comment[fragment mass tolerance] = 0.5 Da` on the 9 Velos rows. Two-step chain: the raw header
   proves MS2 was **ITMS** (ion trap), and MaxQuant applies its ITMS tolerance to ion-trap MS2 —
   0.5 Da in both deposited `parameters.txt`, which is also MaxQuant's default, and the paper states
   "default settings" for all data. The Q Exactive rows' `20 ppm` is the deposited FTMS value
   directly and needs no chain.
3. Set A's `Trypsin/P` and the three modifications. Not from set A's own search (none deposited) but
   from the paper's single "default settings" statement covering all raw data, both other
   `parameters.txt` agreeing exactly, and PRIDE's dataset-level `modifications` field spanning the
   whole deposition.
4. Set A and set D eggs are `fertilized egg stage`. Methods describe one egg-collection protocol
   ("turned, uncleaved eggs ... 60 min post-fertilization"); the abstract says "fertilized *Xenopus
   laevis* eggs"; Fig S1B labels the eggs "60' pf". The stage is not restated per sub-experiment.

## Open questions for the reviewer

1. `organism part = not applicable` on all 74 rows — defensible, but a reviewer may prefer
   UBERON:0000922 (`embryo`) on the 25 embryo rows. It was rejected because UBERON classifies
   `embryo` as an organism, not an organism part.
2. `manual picking` (inference 1 above) — the strongest candidate for challenge.
3. `characteristics[cell identifier]` duplicates `source name`. Required by `single-cell`; no
   independent per-cell ID exists in the paper.
4. **Design note (recorded, not a defect):** set D confounds channel with digest — `egg_dimethyl_A`
   occupies both Light and Medium. That is the study's intent (it *measures* technical variation),
   and the artifact records it faithfully.
