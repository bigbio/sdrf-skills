## Why blocked
The **channel map is documented**: the light channel is the study histone sample, and the heavy channel is the super-SILAC heavy histone standard (one aliquot of one pool per run).

The **sample identity is not documented for any run**. The design has 36 samples:
- MCF7 and MDA-MB-231;
- each × NT (not transfected), E (empty vector) and NTT (KDM5B-NTT overexpression, 24 h);
- each × 6 biological replicates.

This matches the 36 deposited raws, but no run is mapped to a sample:
- The run names (`QEP<date>_RN_GR_Elena_<n>` / `…ELENA_<n>[BIS]`) carry only an injection number.
- Each run is its own MaxQuant experiment, named after the file stem.
- The raw-header sample field is the same within each batch (`H8` / `H3`).
- Table S2 gives L/H ratios per cell line × condition × R#1–6 with no file names.
- No SDRF or experimental-design file was deposited.

Not used (rules 6–8):
- **Run-number pattern.** The runs come in blocks of three (1–3, 7–9, …), which could be read as NT/E/NTT triplets. No source states this.
- **Data-driven cell-line split.** H3K4 me1/me2 L/H in `evidence.txt` separates Elena_1–15 and 37–51 (MCF7-like) from 19–33 and 55–69 (MDA-MB-231-like), consistent with Table S2. This is inference only. The per-run MaxQuant values are too sparse to match runs to Table S2 replicate columns, so they cannot give condition or replicate.

Rule 7 forbids keeping rows with `not available` conditions.
