### Modifications — NO Carbamidomethyl (deliberate)
`comment[modification parameters] = not applicable`. Justification from the **deposited DIA-NN log** (`report.log.txt`, extracted by HTTP-range-reading the central directory of the 2 GB `search_engine_results.zip`, not downloaded): the DIA-NN 1.8.1 command line contains **no `--unimod4`** (so no fixed carbamidomethylation) and **no `--var-mod`** (no variable mods). The sample-prep protocol has **no reduction/alkylation step** (DDM lysis → direct LysC/trypsin digest), so `comment[reduction reagent]` and `comment[alkylation reagent]` = `not applicable`. Adding Carbamidomethyl here would be the classic false-positive that passes validation but is wrong on every row.

### Disease / experimental condition — the hardest call (attack this)
Per **Supplementary Table 4** (histopathology, MOESM3) the 18 donors split into two documented groups, and the deposited `individualN` numbering aligns 1:1 with that table:
- **Individuals 1–13 and 18 (N=14, 616 rows):** no metastatic liver disease, no desmoplasia → `characteristics[disease] = normal` (PATO:0000461). These are risk-reducing-gastrectomy (germline CDH1) donors with no liver pathology. A few have *minimal/mild* steatosis or inflammation but no fibrosis and no chronic liver disease; the study designates them healthy controls.
- **Individuals 14, 15, 16, 17 (N=4, 176 rows):** metastatic liver disease + desmoplasia (disrupted architecture; 14 & 17 also show bridging/periportal fibrosis) → `characteristics[disease] = fibrosis` (**EFO:0006890**).

Cross-check that hardened this mapping: the DIA-NN log encodes each run with its original patient code (`NML#` / `CHTL#`), which I mapped to `individualN` via shared box IDs. Exactly the four CHTL codes in boxes 3/5/8/9 correspond to individuals 14–17, while two other CHTL codes (individuals 13 and 18) are histologically healthy — i.e. **the code prefix is a patient-series label, NOT the disease signal**; Supplementary Table 4 by individual number is authoritative and everything reconciles.

Why `fibrosis` (EFO:0006890) and not something else — alternatives were tested against OLS and rejected:
- `cirrhosis of liver` (MONDO:0005155, exact) — **over-claim**, these livers are not cirrhotic.
- `liver metastasis` / a carcinoma term — **wrong cell**; the annotated hepatocytes are the non-neoplastic tumour-adjacent margin, not metastatic tumour cells.
- `hepatic fibrosis`/`liver fibrosis` in MONDO/DOID → returned congenital/CDG/measurement terms (wrong). EFO `fibrosis` was the only exact, correctly-scoped, allowed-ontology (disease values = MONDO/EFO/DOID/PATO) term. Desmoplasia is by definition a fibrous/fibrotic reaction, and the paper's own framing is "vulnerability to fibrosis / disruption in tissue architecture". `factor value[disease]` mirrors this normal-vs-fibrosis contrast — the study's central comparison.

## Values deliberately left missing, and why
- `characteristics[age]`, `characteristics[sex]`, `characteristics[ancestry category]` = **`not available`**. Supplementary Table 1 reports demographics **only as cohort aggregates** (Healthy: 44.14±16.15 y, 79% female; Desmoplasia: 50.75±5.80 y, 25% female). Per annotator rules, age/sex/ancestry require per-individual mapping; only cohort summaries exist, so these are not assigned per cell (no donor-level demographic inference).
- `characteristics[developmental stage] = adult` is the one demographic added, and only at cohort level (all donors are adult surgical patients) as the SKILL permits.
- `comment[isolation window width] = not applicable` — the Astral MS/MS scheme is **variable-width** (60 variable windows spanning 380–980 m/z, Supplementary Table 2), so a single width does not apply.
- `comment[dia method] = not available` — no PRIDE-ontology term captures "Astral variable-window DIA" (PRIDE offers only SWATH/MSE/HDMSE/SONAR/diaPASEF/generic DIA, none of which is this method).
- `comment[carrier channel]` / `comment[reference channel] = not applicable` — label-free single-cell, no TMT carrier/reference.
