# PXD029320 — annotation report

**Status: BLOCKED.** No SDRF was produced. The dataset is genuine multiplexed single-cell
proteomics, but the TMTpro **channel → sample map** that an SDRF requires does not exist in any
deposited file or in the publication. Annotating it would mean fabricating the identity of every
channel in every run.

Two experimental arms:

- **Diluted standard** (39 raw, `TMTpro2`): 9 channels each loaded with **250 pg** of TMTpro-labeled
  OCI-AML8227 peptide standard, **3 channels per differentiation stage** (LSC/PROG/BLAST), + carrier
  in 126. This is a *dilution standard* → `sample type = standard`, not real single cells.
- **Real scMS** (58 raw, `TMTpro5`/`TMTpro7`): each plex = **14 single cells + 200-cell carrier**
  (channel 126). Balanced design: **4 × CD34−, 5 × CD34+CD38−, 5 × CD34+CD38+** per plex. >110 cells
  measured per method.

## Why it is BLOCKED — the channel→sample map does not exist

An SDRF needs one row per (file × label channel) with a sample identity. For TMTpro16plex that is
97 files × 16 channels ≈ **1552 rows**. The paper gives the plex *composition* (4/5/5 for scMS;
3-per-stage for the standard) but **never states which channel holds which cell / stage**, and no
deposited file records it. Critically:

- The paper explicitly assigns cell identities **post-hoc in Python**: *"FACS data and sort- and
  label layouts were used to create the metadata for each cell"* (SCeptre pipeline). Those
  `FACS.fcs` index-sort files and sort/label layouts are **not deposited** in PXD029320.
- Layouts are **per-plate index-sort** results → they vary between plexes and cannot be inferred
  from a single fixed convention.
- Only 9 (standard) or 14 (scMS) of the 15 non-carrier channels are occupied, so even **which
  channels are empty** is unrecorded.

## What would unblock it

Any one of:
1. The authors' **sort/label layout** (per plex, channel → gate/stage) or the `FACS.fcs` index-sort
   files + the SCeptre metadata table, or
2. A **re-deposition** with per-channel sample names set in Proteome Discoverer, or
3. A supplementary **per-cell/per-channel metadata table** (none currently exists).

With a layout in hand the annotation is mechanical: carrier (126) → `sample type = standard`,
`cells per well = 200` (or 100); each single-cell channel → its gate (CD34+CD38− / CD34+CD38+ /
CD34−), `cells per well = 1`; empty channels omitted. Templates would be
`ms-proteomics + human + single-cell` (**not** `cell-lines` — OCI-AML8227 has no CVCL). Note the
scMS arm was **not** reduced/alkylated (paper: "Carbamidomethyl on cysteine (C) was not set, as
these samples were not treated with TCEP/CAA"), so Carbamidomethyl must **not** be annotated for the
scMS runs; it applies only to the diluted-standard arm.

## Reconciliation (deposited vs annotated)

97 deposited raw runs, 0 annotated — every run is blocked by the same missing channel→sample map.
This is a full block, not partial: neither arm has a recoverable per-channel identity.
