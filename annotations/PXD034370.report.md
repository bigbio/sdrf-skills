# PXD034370 — annotation report

**Verdict: BLOCKED.** The dataset is genuine multiplexed (TMT10plex) single-cell proteomics (SCoPE-MS /
"FUNpro"), but the **TMT channel → sample identity map is not deposited and not published**. Annotating
the single-cell channels would require fabricating which cell (and which DDR phenotype group) sits in
each channel. Per the annotator brief and the house precedent (PXD043473, PXD073250), this is BLOCKED,
not partially annotated.

## Why BLOCKED — the channel→sample map does not exist

An SDRF for a TMT set needs one row per (file × channel) with a sample identity. For the single-cell
channels that identity is unrecoverable:

| source checked | result |
|---|---|
| Paper STAR Methods | Gives run *composition* only ("single cells" in some wells, "two hundred carrier cells" in others; "blank channels (PBS only)" mentioned in the Fig S2B QC). **Never states which TMT channel holds which cell**, nor which channel is Group 1 vs Group 2, IR vs non-IR, or phototagged vs not. |
| `Fig4_proteinGroups.txt` / `Fig4_evidence.txt` | MaxQuant labels channels `Reporter intensity corrected 1..10` per experiment — **numbered only, no identity** (MaxQuant's per-channel sample names live in the undeposited `experimentalDesign`/`mqpar.xml`). |
| `files/all` (authoritative, 44 entries) | 34 raw + 10 MaxQuant txt. **No csv/xlsx/mqpar sample sheet.** |
| Europe PMC `supplementaryFiles` (PMC9243628) | Only `gr3.gif`, `gr5.jpg` (figure images). No per-channel design table. |
| PMC / publisher `mmc1.pdf`, `mmc2.pdf` | Not retrievable via PMC `bin/` (HTTP 404) or Europe PMC. Figure S2A per the text shows MS *settings*, not a channel-to-cell layout; Table S1 is foci-detection ground truth, not a channel key. |

### Forensic channel analysis (data-driven, but insufficient and inconsistent)
I computed the per-channel fraction of total corrected reporter intensity across all 10 Fig4 sets:
- **Carrier channel is consistently ch10 (= TMT131)**: ~78–89% of all signal in every Fig4 set — the unmistakable 200-cell carrier. In the FigS2B single-cell set, ch10 is again dominant (59.6%).
- The **blank position is NOT consistent between runs**: lowest channel is ch8 (TMT130N, ~0.4–0.6%) in every Fig4 set, but in FigS2B no channel is near-zero (lowest ch3 = 1.8%). This confirms the brief's warning that layouts flip between runs, so ch8-as-blank cannot be generalized.
- The remaining 8 channels (single cells) are **mutually anonymous** — intensity cannot tell single cell A from single cell B, and there is **no dedicated reference channel** (consistent with the Methods, which describe only carrier + single cells + blanks, no pooled reference).

So forensics reliably identify only the **carrier**; the blank is run-specific and the single-cell
**identities and phenotype groups — the entire scientific payload of the dataset — are absent**.
Emitting rows that assert "TMT126 in Fig4_2206_S1 = one Group-1 single U2OS cell" would be fabrication.

A partial annotation (carrier + guessed blank + 8× "single cell, phenotype = not available") was
considered and rejected: it cannot fill the study's only factor (DDR group), relies on a blank
assignment that demonstrably varies between runs, and manufactures per-channel single-cell identities
the brief explicitly forbids.

## What would unblock it
- A channel key from the authors (M-P. Chien, Erasmus MC), **or**
- Re-deposition of the MaxQuant `mqpar.xml` / `experimentalDesign` with per-channel sample names, **or**
- A supplementary per-set channel→cell table (Group 1/2, IR status, phototag status) tied to file names.

Given any of those, the arms are trivially addable: carrier (ch10/TMT131, ~200 cells, `sample type =
standard/carrier`, `cells per well = 200`), blank (`cells per well = not applicable`), and the single
U2OS cells (`cells per well = 1`), all `Homo sapiens` / U2OS.

## Verified technical facts (recorded for whoever revisits)
- **Cell line**: U2OS human osteosarcoma, Cellosaurus **CVCL_0042** (stably transfected with
  PB-mScarlet-53BP1). CLO returned no `U2OS` hit; CVCL_0042 is the standard Cellosaurus identifier and
  should be re-verified live before use.
- **Label**: TMT10plex (Thermo Cat#90110, batch VB287465) → mass shift **UNIMOD:737**. NOT TMTpro.
- **Modifications**: static modification **left empty → NO Carbamidomethyl** (no reduction/alkylation
  step is described; do not add it). Variable: Deamidation (NQ) → UNIMOD:7, Oxidation (M) → UNIMOD:35.
- **Enzyme**: Trypsin (Promega). **Dissociation**: HCD. **Acquisition**: DDA. **Search**: MaxQuant 2.0.3.1, SwissProt human (2021-10-08).
- **Instrument — genuine conflict, resolved from raw**: PRIDE says only `Orbitrap Fusion Lumos`; the
  paper/protocol say only `Orbitrap Eclipse Tribrid`. The raw InstModel fields show **BOTH instruments
  were used**: `Fig4_2206_*`, `FigS2A_2195_*`, `FigS2D_2178_*` = **Orbitrap Fusion Lumos**; `Fig4_2227_*`,
  `Fig4_2236_*`, `FigS2C_2363_*`, `FigS3A_2363_*` = **Orbitrap Eclipse**. So `comment[instrument]` would
  have to be assigned per file, not one value for the dataset — neither PRIDE nor the paper is fully right.

## Judgement calls a reviewer should attack hardest
1. **BLOCKED vs partial.** I declined a carrier/blank-only partial annotation. Challenge: is emitting
   just the carrier + a run-specific blank defensible? I judged no — the blank position is inconsistent
   between runs and the single-cell factor is unrecoverable, so the partial adds fabricated structure
   without the dataset's actual variable.
2. **Carrier = ch10/TMT131** is inferred from reporter-intensity dominance, not a deposited statement.
   It is consistent across all 11 measured TMT sets, but it is still forensic.
3. **Instrument split** across two Orbitraps is derived from raw InstModel strings on a sampled file per
   group; a full per-file sweep would be needed before writing per-row `comment[instrument]`.
