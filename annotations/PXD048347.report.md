# PXD048347 — annotation report

**Status: BLOCKED (not annotatable).** Multiplexed TMTpro-18 single-cell proteomics (proteoCHIP /
cellenONE, SCoPE-like with a carrier) of mouse-gastruloid germ-layer cells, with **no deposited
channel → single-cell germ-layer identity map**. No SDRF TSV was produced. The single-cell channels —
the actual biological samples and the study's only factor (germ layer) — cannot be assigned an
identity without fabrication, which the annotator brief forbids.

This is the **single-cell proteomics (SCP) validation arm** of the same study as the already-blocked
**PXD041328**, but it is a **different deposition** (different runs/date/experiment; see below).

## The plex layout IS known (from the detailed protocol) — but the germ-layer map is NOT

Unlike PXD041328 (whose `sample_processing_protocol` was a stub with unfilled placeholders), this
deposition's `sample_processing_protocol` is **detailed and specific**, and it authoritatively fixes the
**channel roles**, uniform across all 28 files:

- **126 = carrier** — "The carrier was created by mixing endoderm, ectoderm, mesoderm, unsorted cells,
  and mESCs at equal ratios ... labeled with TMT126 and a **20-cell equivalent** was printed ... to each
  single cell sample." → a **pooled** sample of defined composition; **not a single cell**.
- **127C = empty** — "The 127C channel was left empty to avoid potential contamination from the 126
  carrier channel." → **no sample**.
- **127N, 128N/C, 129N/C, 130N/C, 131N/C, 132N/C, 133N/C, 134N/C, 135N (16 channels) = single cells** —
  "A subset of gastruloids was first sorted for fluorescence-expressing germ-layer cells using FACS
  (Aria III), followed by ... single cell proteomics on the cellenONE." (The `_GFP` file token matches
  this GFP-reporter germ-layer sort.)

So carrier vs empty vs single-cell **is** recoverable. **What is NOT recoverable is which germ layer
(ectoderm / mesoderm / endoderm / unsorted / mESC) each single-cell channel holds** — and that germ
layer is the entire scientific point of this arm and the study's only factor.

## Why BLOCKED and not a partial annotation

- The **single cells are the dataset**; the carrier (126) and empty (127C) channels are SCP scaffolding.
  A "partial" SDRF containing only the 28 carrier + 28 empty rows would identify **zero** of the 448
  single cells and would not represent the experiment.
- Every single-cell channel in **every** file is equally anonymous — there is no arm/chip/file for which
  the germ layer is deposited, so there is no separable annotatable subset.
- This matches the repository's own standard: in the U2OS SCoPE-MS block (PXD034370) "only the carrier
  is recoverable; the single-cell identities and phenotype groups are not" → BLOCKED; and the sister
  deposition **PXD041328** was blocked for the same missing map. Assigning germ layers here would be
  fabrication, which the brief forbids.

## Technical metadata that WOULD be used (recoverable; recorded so re-annotation is trivial once unblocked)

Not the blocker — provided for completeness. Templates: **ms-proteomics + vertebrates + single-cell**.

- Instrument: **Orbitrap Eclipse** — `MS:1003029` (OLS-verified). FAIMS on, CV −50, standard resolution.
- Label: **TMTpro** — `UNIMOD:2016` (OLS-verified), +304.2071 Da, on peptide N-term + K (static).
- Enzyme: trypsin (LysC+Trypsin digest); precursor 10 ppm, fragment 0.02 Da; DDA (top-10 HCD, NCE 32%).
- Variable mods: Oxidation (M) `UNIMOD:35`; protein N-term Acetyl `UNIMOD:1`; protein N-term Met-loss.
- **No Carbamidomethyl** — the protocol describes **no reduction/alkylation** step (the SCP alkylation
  trap); asserting it would be wrong on every row.
- Single cells: 1 cell/well (cellenONE), 13–30 µm diameter; carrier 126 = 20-cell-equivalent pool.

## What would unblock

A deposited **per-(file × channel) layout table** stating which TMTpro channel in each of the 28 runs
holds which germ-layer single cell (ectoderm / mesoderm / endoderm / unsorted / mESC) vs carrier vs
empty — e.g. a cellenONE isolation/print sheet, the authors' SCP `colData`/sampleAnnotation table, a
Cell Stem Cell supplementary channel key, or a re-deposited PD study with real sample names replacing
the generic `Sample` default. Given such a map, the ~448 single-cell rows plus 28 carrier + 28 empty
rows are straightforward (TMTpro-18; ms-proteomics + vertebrates + single-cell).

## Judgement calls for a reviewer to attack

- **BLOCKED vs partial.** I judged the recoverable carrier/empty roles insufficient to constitute a
  useful annotation, because 100% of the single cells (448/504 rows) remain unidentifiable and the
  germ layer is the study's only factor. A reviewer could argue for depositing the 56 carrier+empty
  scaffolding rows; I considered that a non-representative fragment and chose a full block, consistent
  with the PXD041328 and PXD034370 precedents.
- **Paper not read in full.** As with PXD041328, the STAR Methods/supplementary are paywalled (no
  PMCID). If a supplementary table maps these specific 28 runs' channels to germ layers, the verdict
  would change — but a general design description would still not be a deposited per-(file×channel) map.
- I did **not** brute-force the 20.7 GB `.msf` / 19.9 GB `.pdResult` SQLite stores; they are built from
  the same `.pdStudy` design shown above (all `SampleType="Sample"`), so a different answer is very
  unlikely. A reviewer wanting certainty could query their sample tables.
