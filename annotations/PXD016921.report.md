## Key decisions and evidence

**The instrument question is the whole dataset.** The Methods say *"Orbitrap Fusion Lumos and
Eclipse mass spectrometers were employed for data acquisition"* — so "which runs are Eclipse?" is a
real question, and it propagates: the paper sets HCD NCE to **30%** on the Lumos and **35%** on the
Eclipse. Getting this wrong silently corrupts `comment[collision energy]`. Three independent lines
resolve it to Eclipse for all 6 rows:

1. **Figure 4's caption** enumerates exactly the deposited set — *"100 HeLa cells, 20 HeLa cells,
   four single HeLa cells (SC-1, SC-2, SC-3, SC-4), and zero cells (blank) **using the Orbitrap
   Eclipse**"*. The Lumos runs live in Figures 2–3 (30 µm column; Pierce digest dilutions) and are
   **not deposited**.
2. **Raw file headers** (HTTP range, utf-16-le). All 7 files share one MS device (`TNG-Calcium`) and
   one method host (`2HQF8D2_1 on thermo-1rpc9034`) — one physical instrument. The SII device *alias*
   differs: `Singlecell3` and `100HeLacells` say literally `Orbitrap Eclipse`; the other five say
   `Sodium`. That split tracks acquisition month (May 2019 vs a `KMCH_April2019` folder), consistent
   with a pre-release instrument renamed after the Eclipse's mid-2019 launch — the runs were acquired
   at Thermo (two co-authors are Thermo employees; `KMCH` = author Khatereh Motamedchaboki). The
   alias is a user-assigned label, not the model field, so it is corroboration, not proof.
3. **PRIDE** `instruments: [Orbitrap Eclipse]`.

The brief warns PRIDE's submitter-entered instrument field is demonstrably wrong across this corpus.
Here it happens to be right — recorded because it was verified, not assumed.

**The HeLa S3 trap does not fire — verified, not assumed.** The Materials list *does* include
"Pierce HeLa protein digest standard", which derives from HeLa **S3** (CVCL_0058). But those QC
dilution runs (0.2 / 0.5 / 2 ng) belong to Figure 2 and are **not among the 7 deposited files**. Every
deposited run is nanoPOTS-prepared *"HeLa cells (ATCC, Manassas, VA)"* — parental HeLa,
`EFO:0001185` / `CVCL_0030` (Cellosaurus cross-references `ATCC; CCL-2`, matching the paper).
Per the brief, OLS smart mode was not trusted for `HeLa`; `mode="fuzzy"` returned `EFO:0001185` and
was eyeballed against the alternatives (`HeLa-S3`, `HEp-2`, `HeLa M`, `T-REx-HeLa`).

**Dilution mimics are absent.** The screen flagged that dilution/bulk runs might be mixed in. There
are no digest-dilution runs in the deposit at all. The 20- and 100-cell runs are **real cells**
carried through the full nanoPOTS protocol, not dilution mimics — annotated as `bulk control`
(`PRIDE:0000907`, a genuine child of `Quality Control Sample`), matching the paper's own framing:
*"Samples containing 20 and 100 HeLa cells were analyzed in addition to single cells to facilitate
MBR feature matching."* Single cells carry `single cell` (`PRIDE:0000897`).

**Search settings come from the deposited `mqpar.xml`, not from defaults.** It agrees with the
Methods exactly: `Carbamidomethyl (C)` fixed (UNIMOD:4), `Oxidation (M)` variable (UNIMOD:35),
`Acetyl (Protein N-term)` variable (UNIMOD:1, written `PP=Protein N-term` — a positional value, never
`TA=`). PRIDE's `modifications` field ("monohydroxylated residue, acetylated residue, iodoacetamide
derivatized residue") independently agrees — three mods, same three.

**Tolerances.** `mainSearchTol=5` → `comment[precursor mass tolerance]` = `5 ppm` (paper: *"first
search and main search (recalibrated) were <30 and 5 ppm"*). The FTMS `msmsParams` block gives
`MatchTolerance=30`, `MatchToleranceInPpm=True` → `comment[fragment mass tolerance]` = `30 ppm`. The
FTMS group is the applicable one because MS2 was acquired in the Orbitrap (method name `OTOT`; the
paper sets MS2 Orbitrap resolution to 120 000 / 240 000). Note **30 ppm is not the MaxQuant default**
(20 ppm) — it was deliberately set, and the deposited file outranks any assumed default.

**Label-free confirmed structurally:** `multiplicity=1`, empty `labelMods`, `lfqMode=1`. Hence
`comment[carrier channel]` and `comment[reference channel]` = `not applicable` (no multiplexing
exists to have a channel).

## Judgement calls a reviewer should challenge

1. **`comment[cleavage agent details]` = `Trypsin/P` only.** That is what the deposited mqpar
   configures (`<enzymes><string>Trypsin/P</string>`) and the Methods describe *"trypsin-digested
   peptides"*. But Materials lists *"MS-grade trypsin **and Lys-C** were from Promega"*, and the
   nanoPOTS protocol this paper cites (ref 25) uses both. Lys-C is never stated to be used on *these*
   samples, so it was not annotated. This column describes digestion, not the search — so if Lys-C was
   in fact used, this is an under-statement. Cf. `PXD052416`, which annotated both.
2. **`characteristics[disease]` = `cervical adenocarcinoma` (MONDO:0005153).** Cellosaurus's own
   term for CVCL_0030 is NCIt C27677 *"Human papillomavirus-related endocervical adenocarcinoma"*,
   whose nearest MONDO is `endocervical adenocarcinoma` (MONDO:0000554) — arguably more faithful.
   MONDO:0005153 was chosen to match the existing approved corpus annotation (`PXD052416`), i.e. a
   corpus-consistency choice, not a claim that the more specific term is wrong.
3. **`characteristics[single cell isolation protocol]` = `nanoPOTS`.** The enum also offers
   `manual picking`, and cells were microscope-selected before robotic aspiration. `nanoPOTS` was
   chosen because the platform performs the aspiration and dispensing; the selection is manual.
4. **`characteristics[biological replicate]` = 1–6**, one per distinct nanowell preparation. The
   paper treats individual single cells as biological replicates (*"standard deviations from three
   biological replicate measurements of single HeLa cells"*). The two bulk runs are separate
   preparations from the same suspension and are numbered 5–6 rather than restarting per group.
5. **`factor value[cells per well]`** (1 / 20 / 100) — the variable distinguishing the deposited
   runs (Figure 4). The study's headline comparisons (column i.d., instrument generation) are not
   expressible here because those runs were not deposited.
