# PXD064501 — SDRF annotation report

**Status: BLOCKED** (per project policy — the study's biological factor is not recoverable per channel).

**Decision:** Every single-cell TMT channel is identifiable as one single adult mouse cardiomyocyte, and
a **140-row SDRF was constructed and validates clean** against `ms-proteomics + vertebrates + single-cell
+ clinical-metadata` (all four templates, `parse_sdrf` exit 0, one run each). It is **not shipped**
because the study's core experimental variable — **control vs *Myc*-overexpressing genotype** — is **not
deposited per channel** for these 14 FACS `..._CNIC-KI_TMT{84–98}` runs, so every one of the 112
single-cell rows would carry `genotype`/`factor value` = `not available`, i.e. an SDRF whose only
distinguishing biological axis is absent. This matches the sibling decision for **PXD064518** (analytical
set, same study, same missing factor) and the corpus precedents `PXD025387` (label randomisation) and
`PXD029320` (undeposited per-channel condition map). The structural facts below are recorded so a future
run can annotate it immediately if the per-channel genotype design is supplied. See `annotations/BLOCKED.md`.

## Study and publication

- **Title:** *Pro-regenerative fingerprints identified in a sub-population of adult mouse cardiomyocytes
  by integrative single-cell proteomics* — the **FACS** dataset ("dataset 2").
- **Publication:** Marín-Vicente *et al.*, *Genome Biology* 2026, DOI `10.1186/s13059-026-04110-1`,
  PMID `42174693`, PMC13292336 (gold OA, full text read). PRIDE listed **no** publication (only the
  dataset DOI `10.6019/PXD064501`); the paper was recovered via Europe PMC by title.
- **Design:** single adult mouse cardiomyocytes, FACS-sorted (BD FACSAria Fusion, 100 µm nozzle), TMT
  **10-plex**, RETICLE real-time-search-assisted **DDA** on an **Orbitrap Eclipse** tribrid + FAIMS Pro;
  Proteome Discoverer 2.5 + iSanXoT for analysis.
- **Trio:** PXD064499 (pilot, dataset 1, 12 runs — **annotated**, map deposited), **PXD064501 (FACS,
  dataset 2, 14 runs — this one, BLOCKED)**, PXD064518 (analytical, dataset 3+, 81 runs — **BLOCKED**).

## Organism (verified — not the blocker)

*Mus musculus* NCBITaxon:10090, from PRIDE `organisms`, the paper Methods ("male wild-type mice"), and
the raw filenames (`CNIC-KI`). So `vertebrates` (not `human`) would be the sample template. Developmental
stage = adult (EFO:0001272; "aged over 14 weeks for adults"), sex = male. The neonatal P1 arm in the
paper is *bulk*, not part of this single-cell FACS deposition.

## Deposited vs annotatable (reconciled)

- **Deposited:** 42 files = 14 `.raw` + 14 `.mzML` + 14 `.mzid` for 14 TMT10-plex runs
  `20221019_Ec_01_SC_CNIC-KI_TMT{84,85,87,88,89,90,91,92,93,94,95,96,97,98}` (TMT86 absent). Every
  `files/all` entry's `projectAccessions` was asserted to contain PXD064501 (passed).
- **Channel ROLES are known** (paper Methods + the pilot's deposited iSanXoT `level_creator.tsv`):
  per run, **130N = empty**, **131 = 200-cell booster/carrier** (100 control + 100 *Myc*), and the other
  **8 channels = 4 control + 4 *Myc*-overexpressing single cardiomyocytes**. So a structural SDRF of
  140 rows (112 single + 14 carrier + 14 empty) is constructible and validates.
- **The genotype→channel assignment is NOT known** for these FACS runs → BLOCKED (below).
- The `.mzid` files are X!Tandem/ProteoWizard exports with no `AnalysisSampleCollection`/sample names.
  No PD `.msf`/`.pdStudy`/`.xlsx` sample sheet is deposited.

## The blocker — per-channel control-vs-Myc genotype is not deposited

The single biological variable is control vs *Myc*-overexpressing. Each run holds 4 of each, assigned to
the 8 single-cell channels via **one of two fixed label designs** ("two designs were followed so that
each type … was differentially labelled with alternative tags", Fig. 1c). **Which design each of the 14
FACS runs used is neither deposited nor published.** Assigning genotype to specific channels would
fabricate the study's factor across 112 rows.

Sources hunted, all exhausted (each named):

| source | result |
|---|---|
| Deposited PXD064501 `files/all` | only raw/mzML/mzid; mzid = X!Tandem/ProteoWizard, **no** sample/channel table |
| Paper Methods (PMC13292336, full text) | states 2 designs + composition (4 ctrl + 4 Myc, 130N empty, 131 booster); **not** which design per run |
| Zenodo Complementary_data `10.5281/zenodo.18379944` [40] | analysis code + protein→compartment table; **no** channel map |
| **Zenodo iSanXoT `10.5281/zenodo.19439667` [99]** | full channel→genotype `level_creator.tsv` — **but for the PILOT (PXD064499 = `SST_cnic_SCP_1..12`) only**; maps to those raw files, never to TMT84–98 |
| Zenodo Raw_data_1 `10.5281/zenodo.19484833` [95] — `Metaboanalyst_Fig3a.txt` | the FACS per-cell values, named `{CTRL\|MYC}_{TMT}_{idx}` → confirms 4 ctrl + 4 Myc per run for TMT84–98, but gives the within-genotype index only, **no physical channel** |
| Zenodo Raw_data_1 `median_reporter_ion_intensity_per_TMT.csv` | per-channel medians corroborate 130N=empty / 131=carrier (130N is min in 64/97 runs, 131 max in 73/97); **cannot** separate ctrl from Myc single cells (both are single cells of similar size) |
| GitHub (ref 100) | only the iSanXoT tool docs (`cnic-proteomics.github.io/iSanXoT`); no paper analysis repo |
| Europe PMC supplementary (PMC13292336) | 7 figure images + one methods/tables `.docx` (Figs/Tables S1–S17); no channel key |

**Why the pilot map does not rescue it:** the pilot's two designs are
A = CTRL{126,127C,128C,129C}/MYC{127N,128N,129N,130C} and B = the swap, alternating A,B,A,… by batch
index. Reusing that assumption for a *different* deposition acquired months later on a different LC is
forbidden (the brief bars assuming a fixed layout; the corpus notes layouts flip between runs). A
forensic route — matching the deposited per-scan reporter intensities to the named Z-values in `Fig3a`
to infer each channel's cell — was **deliberately not used**: that is inference from data, not deposited
metadata (the `PXD073250` principle), and would silently assert the factor for 112 rows.

## What is recoverable (for a future run, given the design)

Given a per-FACS-run A/B design table, the annotation is mechanical:

- Templates: `ms-proteomics v1.1.0 + vertebrates v1.1.0 + single-cell v1.0.0 + clinical-metadata v1.0.0`.
- 140 rows (14 files × 10 channels): 112 single (`cells per well = 1`), 14 carrier (131,
  `cells per well = 200`), 14 empty (130N, `cells per well = 0`).
- organism *Mus musculus* NCBITaxon:10090; organism part heart UBERON:0000948; cell type cardiac muscle
  cell CL:0000746; developmental stage adult EFO:0001272; sex male; disease normal PATO:0000461.
- instrument Orbitrap Eclipse MS:1003029; acquisition Data-dependent acquisition PRIDE:0000627; cleavage
  agent Trypsin MS:1001251; dissociation HCD PRIDE:0000590 (38% NCE); single cell isolation protocol
  FACS; facs nozzle size 100 um; carrier channel TMT131; reference channel not applicable.
- labels TMT126…TMT131 (PRIDE:0000516…0000529).
- **Modifications (from the PD 2.5 quant workflow):** TMT6plex UNIMOD:737 Fixed on K and on peptide
  N-term; Oxidation UNIMOD:35 Variable on M; Acetyl UNIMOD:1 Variable on Protein N-term.
  **NO Carbamidomethyl** — the single-cell SCoPE-MS prep (sonication + heat denaturation + trypsin + TMT)
  has **no reduction/alkylation**; DTT/IAA appear only in the separate *bulk* protocol. Asserting
  Carbamidomethyl would be wrong on every row (the brief's reflex-error warning).
- precursor mass tolerance 15 ppm (applied PSM filter; Sequest search window was 800 ppm);
  fragment tolerance not stated → not available.
- **genotype / factor value[genotype]** = the missing piece (control vs *Myc*), plus `strain or breed`
  which co-varies with it. FAIMS CVs (−50 V / −70 V) have no licensed column (known spec gap).

All ontology accessions above were verified live via OLS.
