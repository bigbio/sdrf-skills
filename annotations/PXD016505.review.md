## Findings

1. **minor** (search-parameters) at rows of LDY1098-S20-A-HDAC-F-1.raw, LDY1098-S23-A-HDAC-F-2-No.raw, LDY1098-S23-A-HDAC-F-2.raw (source HDAC1_LDY1098_FOR_pool1_*), comment[precursor/fragment mass tolerance]: One HDAC1 FOR Velos run was not searched, and all three LDY1098 runs carry search tolerances. The manifest says which run is unsearched cannot be determined, but the deposited data narrows it to the LDY1098 vial-BB4 triplet. The -No run is the most likely one.
   - Evidence: Pairwise log-intensity correlations of the HDAC1FOR experiments in proteinGroups_CASP9_HDAC1.txt: FOR3~FOR4 r=0.95 and FOR5~FOR6 r=0.97 (technical pairs); FOR1 is a singleton (Velos scale, = ALI0880); FOR2 is QE scale (3.25e11). The Velos pools are ALI0880 (1 run), LDY1098 (3 runs, vial BB4) and LDY1303 (2 runs), so only 2 of the 3 LDY1098 runs were searched. The raw header of -No names itself LDY1098-S23-A-HDAC-F-2.raw. The deposited F-2 header carries the Xcalibur re-acquisition suffix _130616124905, so -No is the first, smaller (351 vs 519 MB) attempt at slot S23.
   - Fix: Optional. Record the narrowing in the manifest limitation. Or set comment[precursor mass tolerance] and comment[fragment mass tolerance] to 'not applicable' on the 3 rows of LDY1098-S23-A-HDAC-F-2-No.raw, citing the name suffix and the re-acquisition, as the request asks for unsearched runs.

2. **minor** (cross-file consistency) at characteristics[biological replicate] of the SILAC medium rows of the 17 shared RAC1 raws: The same empty-vector source names carry different biological-replicate numbers in the two companion SDRFs (79-84 here, 41-46 in PXD016512). Each file is valid on its own. Merging the two files would give one source two values.
   - Evidence: Cross-file diff of all 51 shared (file,label) rows: identical except this column on the 17 medium rows. Files are byte-identical deposits (same PRIDE size and SHA-1 for all 17).
   - Fix: Optional. Either number the empty-vector sources so the shared RAC1 ones get the same numbers in both files, or give them file-specific source names. The manifest limitation already discloses the difference.

3. **minor** (search-parameters) at comment[fragment mass tolerance] rows 973-1050 (Q Exactive Plus): 0.5 Da comes from the single, search-wide statement in the paper. MaxQuant 1.3 uses a separate FTMS MS/MS tolerance (default 20 ppm) for HCD/Orbitrap spectra.
   - Evidence: Supp. Methods 12 gives 0.5 Da with no instrument split. No mqpar.xml is deposited. The manifest records the caveat.
   - Fix: None required. Keep the manifest caveat.
