### Findings

1. **important** (file_mapping) — file: LDY1098-S23-A-HDAC-F-2-No.raw (missing from comment[data file]); annotations/BLOCKED.md PXD016505 section; manifest limitations: A deposited, real acquisition (351 MB, vs 519 MB for the re-acquisition) of a fully documented arm was dropped. Its arm is HDAC1 FOR, batch LDY1098, vial BB4, the same vial as LDY1098-S20-A-HDAC-F-1 and -F-2. The request says unsearched runs get tolerances `not applicable`, and campaign rule 5 says the same. That keeps such runs in the SDRF. Rule 7 (leave runs out) applies only when the channel map is undocumented, which is not the case here. The claim that this run is the unsearched one is itself an inference: HDAC1FOR has 6 experiments for 7 raws, and nothing ties the missing experiment to -No.  
   Evidence: The raw header (bytes 0-16383) gives the original name LDY1098-S23-A-HDAC-F-2.raw, vial BB4 and LTQ Orbitrap Velos. FTP Content-Length is 350987536. The proteinGroups_CASP9_HDAC1.txt header has 6 HDAC1FOR experiments.
   Fix: Add its 3 rows with the source names HDAC1_LDY1098_FOR_pool1_{HCT116_FLAG-HDAC1,HKE3_EV,HKE3_FLAG-HDAC1} (same vial, so one more technical replicate of that pool) and tolerances `not applicable`. Alternatively keep all search params and state in the limitations that one of the 6 Velos HDAC1 FOR runs is unaccounted. Then remove the "excluded" entry from BLOCKED.md and the manifest.

2. **minor** (provenance) — manifest limitation on out-of-scope experiments: The manifest states that the extra ELK1FOR, ELK4FOR and PXNFOR experiments (8 experiments vs 7 raws each) and the RAF1 experiments (10 vs 7 per direction) are raws in the companion deposits. This is not verified. A file-name scan of the PXD016461-PXD016465 listings finds no ELK1/ELK4/PXN raws, and only 6+6 CRAF raws in PXD016463, which does not account for 3+3. Reword it as an unexplained count mismatch.  
   Evidence: Reviewer FTP listings of PXD016461-465; proteinGroups headers.

3. **minor** (technical) — comment[fragment mass tolerance] (and comment[collision energy]), all Q Exactive Plus rows: 'not available' on the QE rows makes parse_sdrf convert-openms exit 1. Supp. Methods 12 states one search-wide 'fragment ion mass tolerance set to 0.5 Da' with no instrument restriction; restricting it to the ion-trap rows is an interpretation (MaxQuant 1.3 keeps separate ITMS/FTMS settings, but none is deposited). The HCD NCE was not looked for in the instrument-method stream of the raw files: the first 16 KB hold only the Dionex LC method.  
   Evidence: supp1.txt section 12; convert-openms rerun by reviewer: "Cannot read fragment mass tolerance: not available".

4. **minor** (design) — characteristics[biological replicate], SILAC medium rows of the 17 shared RAC1 raws: The same EV source names get different biological replicate numbers in the two SDRFs: 79-84 in PXD016505 and 40-45 in PXD016512. Each file is consistent on its own, because EV numbering runs over all baits in that file. Every other column of the 51 shared rows is identical. Either note this in both manifests or number the EV pools identically in both files.  
   Evidence: Reviewer diff of the 51 rows (17 files x 3 labels): 17 differing cells, all in characteristics[biological replicate] of the medium channel.
