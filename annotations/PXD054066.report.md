## Scope / deposited-vs-annotated reconciliation
- **All 123 raw runs are annotated** (100% coverage), including the 5 blanks. The 4 `.tsv` search reports and `checksum.txt` are not runs and are not annotated.
- **Label-free DIA, no multiplexing** → each raw file = exactly one sample. No channel→sample map is required, so the dataset is fully annotatable; the multiplex-BLOCKED branch does not apply.
- **The deposition is a subset of the published study.** The abstract/Methods describe HeLa, HCT116 5‑FU spheroids, a 96-well/Vanquish-Neo+FAIMS setup, and hi12 iPSC / embryoid-body (EB) differentiation with OCT4/SOX2/GATA4/HAND1/MAP2. **None of the spheroid, FAIMS-plate, iPSC or EB runs are in PXD054066** — the deposited files are only the Evosep-One/Orbitrap-Astral HeLa sensitivity-and-throughput benchmark (single-cell + 20-cell titration), plus 10 hFF single cells and 5 blanks. The Methods also mention 10-, 20- and 40-cell samples and 2Th/4Th/8Th/16Th window schemes; only **20-cell** samples and only **4 Th** schemes are present here. This is stated so a reviewer does not expect the iPSC/lineage-marker content in this SDRF.

## Key technical decisions (all from paper Methods, corroborated by PRIDE protocol text)
- **Instrument:** Orbitrap Astral, `MS:1003378` (verified OLS; matches PRIDE `instruments`).
- **Acquisition:** narrow-window DIA (nDIA). `comment[proteomics data acquisition method] = Data-independent acquisition` (plain string required by the dia-acquisition template; `PRIDE:0000450`). `scan window` 380–980 m/z (full-MS range). `isolation window width = 4` for the 108 files whose names encode `4Th`.
- **Dissociation / energy:** HCD = `beam-type collision-induced dissociation` `MS:1000422`; NCE 27% → `27 NCE`. (The paper's alternate 96-well/FAIMS setup used NCE 25%, but those runs are not deposited here.)
- **Enzyme:** dual digestion trypsin + Lys-C → two `comment[cleavage agent details]` columns: `Trypsin` `MS:1001251`, `Lys-C` `MS:1001309`.
- **Modifications:** `Oxidation` `UNIMOD:35` (M, Variable) and `Acetyl` `UNIMOD:1` (Protein N-term, Variable). **No Carbamidomethyl** — the protocol is DDM-lysis + direct digest with **no reduction/alkylation step**, and both Spectronaut and DIA-NN searches explicitly excluded cysteine carbamidomethylation. `comment[reduction reagent]` and `comment[alkylation reagent]` are therefore `not applicable`. (Acetyl written as `UNIMOD:1`, not the Phospho `UNIMOD:21` swap.)
- **Phospho search NOT annotated per-row:** the paper ran a *separate* phospho-STY search on a subset for the PTM analysis; it is not the standard search applied to all runs, so it is not added to `modification parameters`.
- **Label:** `label free sample` `MS:1002038`.

The file-name token "hFF" supports only the conservative reading *human fibroblast*; it does **not** by itself establish donor anatomy or sex. **CORRECTION (post-review):** the first pass asserted `organism part = prepuce of penis` UBERON:0001332 and `sex = male` by expanding "hFF" to *human foreskin fibroblast*, but the manuscript never mentions hFF/foreskin/fibroblast as a sample, the PRIDE record is silent, and the supplementary tables' apparent "hff"/"fibroblast" hits are false positives (peptide residues `…HFF…`; "Fibroblast growth factor" protein names). An independent reviewer flagged the anatomy+sex as unsupported specificity; both were set to `not available` on all 10 hFF rows. `cell type = fibroblast` (defensible token reading) and `disease = normal` are retained. No specific fibroblast cell line / Cellosaurus accession could be assigned.
- **Blanks** (5 runs): "Master-Mix-buffer only, prepared identically to single cells" (Fig. 3 text) → `sample type = buffer control` PRIDE:0000911; `organism / organism part / cell type / disease / sex / material type = not applicable`; `cells per well = 0`; `single cell isolation protocol` and `cell identifier = not applicable`. They still ran DIA with trypsin/Lys-C in the buffer, so instrument/enzyme/acquisition/label are kept.
- **Isolation:** `single cell isolation protocol = cellenONE` (fixed-enum bare token, not an ontology term) for all cell samples; `not applicable` for blanks.
- **`material type = cell`** for all cell samples (single cells / 20-cell), `not applicable` for blanks.
- **Structure:** `source name` and `cell identifier` are synthetic per-run IDs; `comment[data file]` carries the authoritative raw name. `fraction identifier = 1` (unfractionated), `technical replicate = 1` (each raw is a distinct cell/sample, not a re-injection), `biological replicate` increments within each group.
- **Factor:** `factor value[cell type]` (HeLa cell / fibroblast / not applicable), the clearest sample-distinguishing variable. Placed **last** as `parse_sdrf` requires.

## Values left as reserved words, and why
- `characteristics[age] = not available` for **every** row: cell-line donor age is not a property of a cultured single cell; hFF donor age is unknown; blanks have no donor. `age` forbids `not applicable` (allow_not_applicable=false in the resolved human template), so `not available` is the only legal reserved word.
- `comment[precursor mass tolerance]` / `comment[fragment mass tolerance] = not available`: library-free directDIA+ (Spectronaut v18) and DIA-NN set these dynamically; no fixed tolerance is reported.
- `comment[isolation window width] = not available` for hFF (10) and blanks (5): the window is not encoded in those file names and was not verified from the raw headers. It is `4` only where the name states `4Th`.
- `comment[dia method] = not available`: PRIDE has no term for Orbitrap-Astral narrow-window DIA; the real window width is captured in `isolation window width` instead.
- Blanks use `not applicable` across the biological characteristics (no organism/cell), which is legal for those columns per the resolved templates.

## Conflicts found and how resolved
- **PRIDE `publications` empty** → recovered the Nature Methods paper via Europe PMC and verified it against the abstract before trusting it.
- **PRIDE description vs paper lineage-marker mapping:** PRIDE says "GATA4 (mesoderm), HAND1 (endoderm)"; the paper says "GATA4 (endoderm), HAND1 (mesoderm)". Irrelevant to this SDRF (no iPSC/EB runs deposited) but noted as a PRIDE-vs-paper discrepancy.
- **PRIDE `modifications`** ("monohydroxylated residue", "acetylated residue") and **PRIDE description** (Spectronaut v19) vs paper (Spectronaut v18): the paper Methods were taken as authoritative; the SDRF encodes Oxidation(M) + Acetyl(protein N-term), which both sources agree on. Version numbers are not SDRF fields.
- **Cross-workflow parameters:** description mixes the Evosep (NCE 27, 4 Th, 380–980) and the 96-well/Vanquish-Neo/FAIMS (NCE 25, 20 Th, 400–800) acquisitions. Only the Evosep runs are deposited here, so the Evosep parameters were used throughout.

## Judgement calls a reviewer should attack hardest
1. **hFF identity is inferred from a file-name token** — the paper does not mention it. RESOLVED post-review: the overreaching `organism part = prepuce` and `sex = male` were withdrawn to `not available`; only the conservative `cell type = fibroblast` and `disease = normal` remain. If it is a different fibroblast source even those are wrong, but they no longer assert donor anatomy/sex.
2. **Not using the `cell-lines` template for HeLa.** `characteristics[cell line]` forbids both reserved words, which would force excluding the hFF and blank runs (the documented #35 B1 trap). To keep all 123 deposited runs in one file, HeLa identity is carried by `cell type = HeLa cell` (CLO) + organism part + disease, matching this repo's prior SCP annotations (e.g. PXD046467). Cost: no CVCL/cell-line column. A reviewer may prefer a `cell-lines` SDRF over the HeLa subset instead.
3. **HeLa disease = cervical adenocarcinoma** (MONDO:0005153) — HeLa's histology is debated (adeno- vs squamous/epidermoid); Cellosaurus and prior repo practice use adenocarcinoma.
4. **20-cell samples as `pooled`** rather than `standard`/`bulk control` — they are 20 cellenONE-sorted cells, so "pooled" was chosen over the dilution-standard reading.
5. **Blanks included** (not excluded) as `buffer control` with biological fields `not applicable`; a reviewer may argue blanks should be dropped from an SDRF entirely.
6. **`sex = female` for HeLa** is inferred from cell-of-origin, not stated per-sample in the deposited metadata. (hFF `sex` was withdrawn to `not available` post-review — see #1.)
