## Study

Human oocyte proteome **and secretome**. Pools of 100 oocytes established the reference proteome;
SP3 (Hughes et al., Mol Syst Biol 2014) then scaled the workflow down to **individual oocytes**,
comparing germinal-vesicle (GV, immature) against metaphase-II (MII, mature) cells.

## Templates

`ms-proteomics v1.1.0`, `human v1.1.0`, `single-cell v1.0.0`.

`single-cell` is declared even though only 6 of 21 rows are true single cells: it is the template
that licenses `characteristics[cells per well]`, `[sample type]`, `[cell identifier]` and
`[single cell isolation protocol]` — precisely the columns needed to *distinguish* the single
oocytes from the pools. Without it the deposition's central distinction would be inexpressible.

No `cell-lines` (primary cells). No `dia-acquisition` (DDA). No `clinical-metadata` — unlike
`PXD023366`, no free-text factor column is needed here (see "The factor is a real ontology column"),
so declaring it would license nothing that is used.

### Pools are not single cells — the reconciliation

Only the **6 `140818SL_*_single oocyte.raw` files are true single cells** (`cells per well = 1`,
`sample type = single cell`, `cell identifier = GV3…MII5`). Every other run is a pool or a medium
sample and is annotated as such. The 12 pooled runs carry `cell identifier = not applicable` and
`single cell isolation protocol = not applicable`; a downstream SCP consumer filtering on
`cells per well = 1` recovers exactly the 6 genuine single-cell runs.

## PRIDE exposes ZERO raw filenames — everything came out of the ZIPs

The archive holds **8 ZIP bundles, not 18 raw files**. `files/all` returns only the zips, so neither
the MCP tool nor the REST endpoint yields a single `comment[data file]` value. The raw names, the
labelling scheme, the enzyme, the modifications and the analyzer were all recovered by
**HTTP-range-reading the ZIP central directories and stream-inflating individual members** — no
bulk download (the raw bundles total ~6.9 GB). The deposited MaxQuant `txt` outputs turned out to be
a complete curator key.

## Key decisions and evidence

**The dimethyl channel→sample map is stated outright — this dataset is annotatable.**
`10oocytesdimethyllabeling_txtfiles.zip::txt/experimentalDesignTemplate.txt`:

```
141030SL_Klun_GV-MII_1-10-Ooc	1	immature_light-mature_heavy1
```

and `summary.txt` fixes the chemistry: `Multiplicity = 2`, `Labels0 = DimethLys0;DimethNter0`,
`Labels1 = DimethLys8;DimethNter8`. So **light = immature = GV** and **heavy = mature = MII**,
mapped to `DIMETHYL0` (PRIDE:0000848) and `DIMETHYL8` (PRIDE:0000852) — PRIDE's label terms match
MaxQuant's Lys0/Lys8 nomenclature exactly (+28.03 vs +36.07 Da). No fabrication was needed; had this
file been absent the 10-cell arm would have been unannotatable.

**Instrument — the artifact contradicts PRIDE.** PRIDE's `instruments` field says
`LTQ Orbitrap Velos` (MS:1001742). Range-reading the Thermo raw headers (utf-16-le) returns
**`Orbitrap Velos Pro`** in every bundle sampled — as the Xcalibur device name
(`Creator: Orbitrap Velos Pro`, repeated in the InstrumentID block) and inside the instrument
method (`Waters ACQUITY | Orbitrap Velos Pro MS | LTQ`). Annotated as **MS:1003096**, the PSI-MS
term that exists for exactly this model. Per the brief, raw headers outrank PRIDE's
submitter-entered field. **Flagged for the reviewer** as the main judgment call: `Thermo Finnigan
LTQ` also appears in the same header block, and the single-oocyte instrument was nicknamed `Jerry`
in Xcalibur, so its device-name field does not independently confirm the model — the method-file
string is the evidence there.

**Fragment tolerance is 0.5 Da, not 20 ppm — the trap that `parameters.txt` sets.**
`parameters.txt` lists *both* `MS/MS tol. (FTMS) 20 ppm` and `MS/MS tol. (ITMS) 0.5 Da`; taking the
first is the obvious error. `msms.txt` settles which applies: **every** identified spectrum in all
four bundles is `Fragmentation = CID`, `Mass analyzer = ITMS`. MS2 was acquired in the ion trap, so
the ITMS setting governs → `0.5 Da`, and `comment[dissociation method] = collision-induced
dissociation` (MS:1000133).

**`mature1`/`mature2` are technical replicates, not fractions.** The MaxQuant design assigns them
different `Fraction` numbers (1,2 / 10,11 with gaps at 5,15), which naively reads as fractionation.
Measured instead: peptide-sequence **Jaccard overlap 0.741** (mature1 vs mature2) and **0.763**
(immature1 vs immature2), over an identical 5–142 min RT span — versus 0.601 for the *cross-group*
mature-vs-immature comparison. Real orthogonal fractions would overlap ~0.05–0.2 and occupy
different RT/peptide space; ~75% overlap across the full gradient is repeat injection. The Fraction
column is bookkeeping to make MaxQuant merge the runs into one Experiment. Annotated
`fraction identifier = 1` throughout, with `technical replicate = 1|2`.

**The factor is a real ontology column.** GV/immature = `primary oocyte` (CL:0000654, "has not
completed meiosis I"); MII/mature = `secondary oocyte` (CL:0000655). Because the study's variable
*is* the maturation stage, `characteristics[cell type]` carries it natively and
`factor value[cell type]` needs no free-text column and no extra template — unlike `PXD023366`,
where IVM-vs-IVO could not be separated by cell type and forced `characteristics[phenotype]` plus
`clinical-metadata`.

**Modifications** (from `summary.txt` per bundle, not from PRIDE): `Carbamidomethyl` fixed on C
(UNIMOD:4), `Oxidation` variable on M (UNIMOD:35) everywhere. `Acetyl` variable on
`PP=Protein N-term` (UNIMOD:1 — **not** the UNIMOD:21 Phospho swap) was searched **only** in the
single-oocyte bundle; the third `comment[modification parameters]` column is therefore
`not applicable` on the other 15 rows. In the dimethyl bundle `Acetyl (Protein N-term)` appears
under `Variable modifications first search` but `Use variable modifications first search = False`,
so it was *not* applied — a distinction worth stating, since the string is present in the file.
Dimethyl itself is expressed in `comment[label]`, not as a modification parameter, matching
MaxQuant's treatment of it as a label rather than a variable mod.

**`comment[sample preparation batch]`** = `batch_130403|130724|140818|141030`, the acquisition-date
prefix shared by each bundle's filenames. This is a derived batch key, not a stated one; it is
recorded as a batch identifier (files sharing a prefix were demonstrably processed together) rather
than as `comment[acquisition date]`, which would assert a date I have not confirmed from the raw
timestamps.

## The paper is unreachable — and why that was survivable

`is_open_access: false` was **not** taken at face value; every route in the brief was exhausted:

| route | result |
|---|---|
| `get_full_text_article(PMC4974340)` | HTTP 404 — not in the OA subset |
| `get_pdf_by_unpaywall(27215607)` | resolves DOI, `oa_status: hybrid`, `license: cc-by` → download **HTTP 403** |
| Europe PMC `supplementaryFiles` | `errorBean: "Article with id PMC4974340 is not open access one"` |
| Europe PMC `?pdf=render` / `fulltextRepo` | 403 |
| NCBI PMC OA service (`oa.fcgi`) | `idIsNotOpenAccess` |
| PMC `/pdf/`, mcponline.org, ScienceDirect (`S1535947620334927`) | 403 / bot wall |

Europe PMC reports `inEPMC=Y, hasPDF=Y, license="cc by"` — the article is nominally CC-BY, but no
machine-reachable copy exists. **The abstract was retrieved** (`get_article_metadata`); the Methods
were not.

This did not block annotation because the deposited MaxQuant `txt` outputs are *better* evidence
than Methods prose for everything the SDRF needs: they are the actual search settings, not a
description of them. They supplied labelling scheme and channel map, enzyme, modifications,
multiplicity, mass analyzer, tolerances, FASTA and MaxQuant version. What the paper would have
added — donor demographics and the isolation protocol — is exactly what is left `not available`
below.

**The abstract independently corroborates the structure of the annotation**: "Starting from **100
oocytes** collected via a novel **serum-free hanging drop culture system**" (→ `cells per well = 100`
for the pool arm, and the secretome/control-medium design); "the first **proteome and secretome**
maps of human oocytes"; "Exploiting **SP3** … we scaled down proteome analysis to single cells …
∼450 proteins from individual oocytes"; "comparing **individual oocytes at the germinal vesicle
(GV) and metaphase II (MII)** stage" (→ the single-cell arm and its GV/MII factor). It says nothing
about the 10-oocyte dimethyl arm — which is annotated purely from that bundle's own MaxQuant
design — and nothing about donors, matching the gaps left `not available`.

### Sibling depositions

The abstract states the study's data are "available via ProteomeXchange with identifier
**PXD004142**". PXD003691 is therefore not the accession the paper advertises. PXD003121,
PXD003691 and PXD004142 all carry PMID:27215607 and are being annotated separately; this report
covers **only the 18 runs deposited under PXD003691**, which were reconciled against
`files/all` for this accession alone. Whether the other accessions re-deposit any of these same
runs was **not** investigated and is out of scope here — worth noting for anyone merging the three.

## Values deliberately left `not available` / `not applicable`

| column | value | why |
|---|---|---|
| `characteristics[age]` | `not available` | No donor ages in PRIDE; paper unreachable. `allow_not_available=true`, `allow_not_applicable=false` — so even the control-medium row must say `not available`, which is semantically awkward but the only legal token. |
| `characteristics[disease]` | `not available` | No source states a diagnosis. These are presumably ART patients, but "presumably" is not evidence — the tempting fabrication (`female infertility`) was refused, as in `PXD023366`. |
| `characteristics[individual]` | `not available` | No donor mapping anywhere. **`GV3`/`MII3` were NOT assumed to share a donor** — the numbering 3,4,5 is suggestive of nothing verifiable. |
| `characteristics[ancestry category]` | `not available` | Not stated anywhere; correctly *not* inferred from the authors' affiliations. |
| `comment[precursor mass tolerance]` | `not available` | MaxQuant 1.3's `parameters.txt` genuinely omits first/main-search precursor tolerance, and `mqpar.xml` was not deposited. The MaxQuant 1.3 defaults (20 ppm first / 6 ppm main) were **not** written in — they would be a guess about a setting no deposited artifact records. |
| `characteristics[cells per well]` (secretome) | `not applicable` | The analyzed material is conditioned medium; the oocytes were not lysed into it. Writing `100` would imply 100 lysed cells and corrupt any SCP normalization keyed on this column. The ~100-oocyte provenance is recorded here instead. |
| `characteristics[material type]` (secretome) | `not applicable` | Enum is `tissue, cell, cell line, organism part, whole organism, synthetic` — conditioned medium is none of them. |

`characteristics[sex] = female` is not an inference — oocyte donors are female by definition.
The control-medium row is `not applicable` for it, having no donor.

## Inferred vs stated — the honest ledger

**Stated** (deposited artifacts): all raw filenames; dimethyl light=immature/heavy=mature; 2-plex
multiplicity; Trypsin; Carbamidomethyl/Oxidation/Acetyl; CID+ITMS; 0.5 Da; label-free multiplicity
for the 100-cell, single-cell and secretome bundles; MaxQuant 1.3.0.5.

**Inferred, and flagged:**
- **`single cell isolation protocol = manual picking`** (6 single-cell rows). The column is
  `required` with `allow_not_available=false`, so an enum member was mandatory. No source states the
  transfer method. PRIDE describes hanging-drop incubation and SP3 in a single vial, with no
  FACS/nanoPOTS/microfluidics/LCM anywhere; oocytes are ~100 µm cells routinely handled by mouth
  pipette. `manual picking` is the only enum member not contradicted by evidence — the same call
  the reviewer accepted for `PXD023366`.
- **`cells per well = 100`** for the 100-oocyte pools, and **`= 10`** for the dimethyl pools. From
  the zip names (`100oocytesmature-immature`, `10oocytesdimethyllabeling`), the PRIDE description
  ("pools of 100 cells", "in bulk (10-100 cells)") and the abstract ("Starting from 100 oocytes").
  Three independent sources agree on 100; the `10` rests on the zip name and "10-100 cells" alone.
  Both are the deposition's own round numbers and may be approximate.
- **`Orbitrap Velos Pro`** over PRIDE's `LTQ Orbitrap Velos` — see above.
- **`batch_*`** from filename date prefixes.
- **Secretome rows carry their own `source name`s** (`secretome_130724_mature`, …) rather than
  sharing the pools' `source name`. The 130724 sample numbering (1=oocytes-mature,
  2=secretome-mature, 3=oocytes-immature, 4=secretome-immature, 5=control-medium) plus the
  hanging-drop description makes it *very likely* that `secretome_130724_mature` is the medium from
  the very same ~100 oocytes as `pool100_130724_mature`. **That pairing is implied, never stated**,
  so it is documented here rather than asserted as a shared sample identity in the artifact.
  **Reviewer: this is the second judgment call worth challenging** — if the pairing is accepted,
  the two should share a `source name`.

## Design notes (properties of the study, recorded not corrected)

- The four sub-experiments are **fully confounded with acquisition batch** (single cells = 140818,
  dimethyl = 141030, pools+secretome = 130403/130724). Cross-arm comparison is not supported;
  within-arm GV-vs-MII is.
- The 100-cell arm has only n=2 biological replicates per group, one of which (130403) is a single
  injection on a longer gradient (~3,000–4,700 peptides) versus ~8,700–9,100 for 130724 — a visible
  depth difference between the two batches.
- The single-cell arm is n=3 vs n=3 with no donor information, so donor-vs-stage confounding
  **cannot be assessed at all** from the deposition.
